# Internal Prism API

> **Status:** Current

The preload bridge exposes these domains: projects, credentials, services, workflows, assets, assistant, generation, history, and experiments.

Canonical executable definitions:

- Interface: `src/shared/types.ts` (`PrismAPI`)
- Renderer bridge: `src/preload/index.ts`
- Main handlers: `src/main/index.ts` (`registerIpc`)

Every method requires a one-to-one typed interface entry, preload invocation, registered main handler, argument validation, authorization checks where privileged, and regression coverage. Generated channel-registry validation should prevent undocumented or orphaned IPC methods.

The services domain includes fal.ai profile list/refresh, add/sign-in, disconnect/reconnect/sign-out/delete, rename, default selection, and per-project selection. Renderer responses contain profile metadata only. Generation resolves project override versus global default and decrypts the selected profile entirely in the main process.

## fal generation request ownership

Main creates one SDK client per generation with the selected protected profile credential and Electron transport. Input and reference uploads, enqueue, status/results and cancellation use that client. The shared SDK singleton is not configured. New POSTs revalidate the original project/profile request owner after asynchronous preparation; obsolete work cannot enqueue a new generation. Already initiated uploads and owned status/result/cancel requests retain original account ownership.

The generation abort signal stops local polling and requests remote cancellation once the enqueue ID is known, including an abort while enqueue is returning. Cancellation uses the original client and an independent bounded signal; it does not reuse the aborted polling signal. The listener is removed when the subscription ends. A failed cancellation yields an explicit remote-job uncertainty error, rather than a silent successful stop. The existing generation.cancel boolean acknowledges the local controller abort; it does not prove remote termination. An abort before any request ID is returned cannot prove that the provider created no job. Authenticated remote cancellation/recovery remains a separate verification gate.

## Selected fal model contract discovery — 9 October 2026

Source foundation; desktop installation and renderer/execution consumers remain pending. `services.falSchema(endpointId)` invokes `services:fal-schema` and returns a public `FalSchemaContract`. Main validates the exact catalog ID before transport, loads the selected project/profile credential privately, and reads only the fixed `/v1/models?endpoint_id=...&expand=openapi-3.0` discovery URL. This is read-only discovery; schema data cannot initiate inference, dereference external references, or choose another transport origin.

Responses are bounded to 8 MiB and must contain exactly one active 2D inference model matching the requested ID, without continuation. Compilation and validation use bounded workers with deadlines and 32 MiB JavaScript heap limits, so schema reference expansion, regular expressions and alternatives do not run on Electron's UI/main thread. Compilation permits local references and supported declarative rules only. The result contract is taken from the queue-result operation paired with its input operation, never from enqueue status.

The provider may declare a different OpenAPI path namespace from the catalog ID. `schemaPath` identifies that declared input/result pair for binding only. `endpointId` remains the sole execution identity. Multiple alternate POST paths are rejected unless the exact catalog path is present. Declared JSON types, enums, defaults, format annotations and field ordering are retained. Format annotations do not authorize media URLs; media/path validation remains a separate main-process obligation. No execution-time type coercion, silent default-model substitution, or discarded unsupported rules is allowed.

A five-minute selected-project/profile cache retains at most 64 endpoints, coalesces each pending lookup and never evicts one before settlement. At most eight schema transports run simultaneously, including obsolete-scope requests until they actually finish. Ownership is checked around transport, body reads, compilation and cache publication. A profile/project change clears current retention; a failed or stale refresh never supplies a runnable stale contract.

Current evidence covers captured public schemas, mocked transport/ownership/cache races, pathological validation, and compiled worker/bridge checks. Full live menus, model controls, graph roles, exact payload compilation and authenticated inference remain separate required integration gates.

## Native audio contracts — 9 October 2026

**State:** implemented and tested in source; not yet in the installed application. No additional IPC surface or dependencies. `GenerationRequest` remains the typed boundary and the main process remains the sole credential, transport and persistence owner.

Direct ElevenLabs Speech and Dialogue retain separate authored documents. Dialogue sends ordered `{ text, voice_id }` inputs to `/v1/text-to-dialogue` (or its timestamps variant), with `settings.similarity`; single-speaker `similarity_boost` is not substituted. Main validates current model support, at most ten unique voices and a conservative 2,000-codepoint total before transport. Unknown future model IDs require an explicit live dialogue capability. Exact text, zero settings and turn identity are preserved; no split, trim or deduplication occurs. Only validated, allowlisted timing/speaker metadata is retained.

Native Fish uses `fishAudio.ts` for both request preview and main compilation, `fishCatalogDiscovery.ts` for public contract discovery, `fishAudioApi.ts` for the one TTS request, and `fishAudioPersistence.ts` for owned result storage. `services.models('fish')` reads the exact `/v1/tts` model header and JSON body contract from the fixed official public OpenAPI URL. This requires no credential or account read. The reader has a ten-second deadline and a two-MiB body limit; it rejects ambiguous, unsupported and external schema references. The existing bounded schema worker compiles and validates the body. Provider data cannot select a transport origin.

The public read is coalesced; retained catalogs are scoped to the existing project/profile request owner and expire before the renderer's ten-minute refresh. Availability includes source URL, content fingerprint, timestamp and the native input schema. `verified` means a validated advertised public contract, not account access or actual executed-engine attestation. A failed refresh preserves stale choices for inspection; stale, absent, withdrawn or expired selections cannot run. Existing startup, timed and manual refresh consumers include Fish independently of account connectivity.

Fish submission checks owner, cancellation, exact text/model, numeric settings, format/rate combinations, the fresh advertised model and the complete current body schema before loading a credential. Transport uses the fixed `/v1/tts` endpoint and an explicit model header; it does not accept the provider's implicit fallback. Opus UI kbps convert to wire bps; MP3 kbps remain unchanged. Invalid values are never clamped or silently replaced. Audio bodies are bounded to 96 MiB with a 120-second cancellation deadline and error bodies to eight KiB.

The published S1 retirement date has no timezone. The implementation conservatively blocks S1 at the earliest global start of 31 December 2026 (30 December 10:00 UTC), requiring explicit migration rather than the advertised silent S2.1 substitution. The response identifies the requested engine only; the service does not attest which engine actually executed.

Evidence: 1,611 pure tests across 202 actual files, TypeScript/build, actual main-handler composition, captured official body schema, changed-required-field rejection before credential/POST, native controls at 250/315/375px, and production AppNext save/reopen through isolated disk JSON. Transport and generation were mocked; no credentials, user project, paid generation or remote inference were exercised. Newly required unknown fields fail before submission. Automatic editing of every future/complex field, Fish voice-library search/sample and multiple-speaker/MessagePack inputs remain required follow-on work.


## Direct native image references — 9 October 2026

Source implemented and mocked-main composition verified; not installed or live-inference verified. Direct OpenAI and Google plan every ordered reference before credentials. They preserve the same physical-input/anonymous-prompt ordinal order, including primary and URL-only inputs. A managed path remains authoritative when a reference also has a URL: unreadable local data does not silently fall back. `.prismstyle` metadata remains an intentional non-image input.

Owned PNG/JPEG/WebP bytes are bounded to50MiB per image/100MiB per request, checked before reading and checked again against the read length. These are conservative implementation bounds, not a claim of every provider's maximum. Unsupported media, excessive count, malformed inline data, unavailable path, cancellation or stale request ownership blocks before a new provider POST. Public remote images are passed as credential-free HTTPS URIs without a local media fetch; credentials, local/reserved literal hosts and unsupported protocols are rejected. DNS/remote-image content is not inspected by this URI-only adapter.

OpenAI local-only inputs retain multipart `image[]`. Mixed/URL edits use documented JSON `images: [{ image_url }]`, with local bytes encoded as data URLs in their original positions. Inline strings obey the20MiB declared URL-string bound. Google uses inline `data` for owned/data-URL inputs and `uri` for public URLs; it omits an unknown MIME rather than guessing one from an opaque URL. Its encoded JSON request has a20MiB implementation bound. Only requests with no effective input use text-only generation.

The pure `directImageControls` owner is shared by request inspection and both main adapters. OpenAI reports actual model/size/output_format/n; Google reports actual model/response_format. Ignored seed/guidance/steps are no longer presented as transmitted direct-image controls. Batch quantity remains renderer execution policy; each OpenAI call explicitly requests one output. This does not establish complete native model controls, masks, dynamic image-contract discovery, remote content/type inspection, locked-artwork URL compositing or result-persistence security.

Primary contracts: [OpenAI image edit](https://developers.openai.com/api/reference/resources/images/methods/edit), [Google ImageContent](https://ai.google.dev/api/interactions-api#ImageContent), [Google ordered image inputs](https://ai.google.dev/gemini-api/docs/image-understanding). Baseline probes reproduced both routes dropping a URL-only edit; repaired actual dispatcher fixtures inspect the one mocked POST and prove preflight errors produce no credential load/submission. No real keys, uploads, downloads, inference or user projects.
