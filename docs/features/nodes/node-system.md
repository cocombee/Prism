## Canvas and nodes

- Use a dark infinite canvas with pan, zoom, selection, typed connectors, node search, history, local assets, and reusable workflows.
- `nodeInputPorts` is the single source of truth for connection topology and cardinality. Derive quick-connect menus, destination-handle selection, and connection limits from the exact target node/model's declared ports, filtered through the same central validator used for drag commit and provider assembly. Never keep separate hand-authored signal-to-target lists or hardcode limits by handle name. Start Image, End Image, source Video, Storyboard, Style, and Router inputs accept one edge; Seedance Video Reference and Audio Reference accept three; text, semantic/general Reference, Gallery media, and List collection inputs are unbounded. For every source, target, model, and handle the validator accepts or a menu advertises, an invariant test must prove that the target declares the handle and enforces its declared maximum. After every dynamic Image, Video, or Upscaler model change, centrally reconcile all existing incoming edges against the new declaration: preserve an unchanged valid handle, otherwise remap only to a handle representing the same semantic role, and explicitly disconnect with one notice when no compatible role exists. Character/Element/Location/Style, Start Image, and End Image may never cross-remap. Remeasure React Flow node internals after the port set changes so surviving/remapped wires snap to the newly rendered sockets immediately.
- Marquee selection uses partial intersection globally: select and highlight a node as soon as the mouse-drawn selection rectangle overlaps any visible portion of its rendered bounds, however small. Never require the selection rectangle to fully contain a node.
- Add Node begins with the three pinned popular entries in this exact order: Prompt, Image Generator, Video Generator. Follow them with one restrained half-pixel visual separator, then list every remaining available node once in alphabetical display-name order. Search filters this same canonical ordering. Every listed node uses a unique, semantically appropriate icon; automated catalog validation must fail on duplicate icon assignments or ordering drift.
- Maintain one shared semantic icon registry across Projects Home, project cards, project navigation, Assets categories, Add Node, node headers, generator input tiles, and typed ports. A project/card uses a simple folder glyph rather than a workflow glyph or generated initial; Canvas uses a layout/canvas glyph; Assets uses a library glyph; opening a `.prismflow` uses a document-import glyph. Reuse one action glyph everywhere (`Link` for Connect, gear for Options, upward export for Export), while distinct concepts never borrow a nearby but misleading glyph: Frame, Router, Gallery, Generated Media, Sticky Note, Comment, Sticker, Storyboard, generic image reference, semantic reference, source video, reference video, and audio each retain their own relatable symbol. The same named concept uses the same simple, distance-readable silhouette everywhere: Character remains one person, Element one box, Location one landscape, Prompt one message, Video one video, and Audio one waveform regardless of socket capacity. Plural, grouped, or stacked glyphs are reserved for controls whose actual concept is a collection, multiple references, or a media batch—not merely a single named type that happens to allow more than one edge. Provider names continue to use recognizable company marks rather than this generic product registry.
- Keep Add Node in the left toolbar and remove its duplicate from the top-right action bar. Replace the former top-right Add Node position with independent Illustrator-style icon buttons—never a shared visual wrapper—for Align Left, Align Horizontal Centers, Align Right, Align Top, Align Bottom, Distribute Equal Horizontal Gaps, and Distribute Equal Vertical Gaps. Alignment uses actual rendered node bounds, ignores locked nodes, and enables only when enough nodes are selected. Distribution requires at least three nodes, preserves the two outermost bounds on its chosen axis, and calculates equal visible gaps from actual rendered widths or heights. The remaining left tools are Select, Pan, Cut Connection, Frame/Area, Undo, Redo, and Settings as applicable. Remove collaboration-only Notes and Comments. Give every tool a familiar shortcut and tooltip/name.
- Blank-canvas starter presents six actions in a 3×2 grid: Image, Video, Character, Location, Element, Storyboard. Each creates the correct ready-made route.
- Dropped local media creates a media node.
- The outer node shell keeps `overflow: visible` so React Flow ports and hover actions remain reachable. When image, video, upload, generated output, gallery, Storyboard, or reusable media reaches an outer node corner, the terminal painted media wrapper owns the matching radius and clipping. Never hide overflow on the whole node; intermediate generator stages use only their own local media boundary.
- Node header pattern is an icon tile, Node Type title, and concise dynamic subtitle inside the card header. Do not use the old floating title.
- Show a renameable `@asset-name` above the header only for uploaded, existing, saved, compiled, or generated materialized assets. Empty generators, prompts, and unmaterialized semantic nodes do not get `@`.
- Keep the hover toolbar reachable while moving toward it and use direct actions rather than nested menus. There is no Run chevron/dropdown and no More button. Runnable nodes order the toolbar exactly as Run, Connect, Duplicate, Lock/Unlock Position, Rename when eligible, then Delete always last. Run remains present but greyed with its exact readiness tooltip whenever prerequisites block it. Non-runnable utility nodes omit Run and Rename but retain Connect, Duplicate, Lock/Unlock, and Delete last. Pen means Rename and appears only on user-owned materialized assets; empty generators/planning nodes and built-in/application Style presets never expose it. Built-in/application preset `@asset` tags are read-only as well, so hiding Pen cannot leave a second rename path. A custom user-created saved Style remains renameable. Deleting a built-in Style node removes only that canvas instance and never mutates the immutable preset library. Focus remains double-click/`Shift+F`, and Run From Here remains in the contextual workflow menu. Every icon needs its action-specific custom tooltip and every assigned shortcut uses square brackets.
- A materialized node's hover toolbar sits fully above its visible `@asset-name`, separated by a small optical gap. Keep it reachable with a short interactive hover-grace interval across the resulting vertical distance; never extend a pointer-capturing bridge across the editable name, and never let painted toolbar chrome or icons collide with the name.
- Generator action is one Play control with estimated cost on hover. During execution it becomes Stop; after completion it becomes Rerun. Rerun uses the standard single-arrow clockwise Rotate glyph with one clear arrowhead; never use a compact two-arrow refresh glyph or a hand-drawn small path whose arrowhead collapses into a hook. Stop uses one plain filled rounded square with no surrounding glyph circle, because the action button already supplies the circular boundary. Both decorative glyphs ignore pointer events so the complete elevated circular button and tooltip wrapper own one reliable click target above node chrome. Do not add a second Generate button or a decorative output-type pill.
- Estimated cost is hover/focus-only before a run. It dismisses on pointer/focus departure, outside pointer interaction, preview opening, app blur, and visibility loss; only an actively running countdown may remain persistent.
- Image and Video generators do not render passive completion/model or idle routing banners beneath the prompt. Completed media plus the Rerun action are sufficient. The status slot appears only for active progress or actionable errors, with equal vertical padding and no duplicate native tooltip for already-visible text.
- Clicking a connection may select it. Hover must remain on a connection for 500 ms before Add Node and Cut actions appear at its midpoint; leaving before 500 ms cancels the reveal. Cut removes the connection. Add inserts a compatible node.
- Right-click menus contain only context-relevant actions; avoid duplicating primary controls and avoid collaboration actions.
- Blank canvas and ordinary node hover/drag movement use the normal system arrow; explicitly override React Flow's built-in `.selectable`, `.draggable`, and `.dragging` pointer/grab cursors outside active pan gestures. The visible grab Hand and primary-button canvas grab mode are exclusive to temporary Space-to-pan: remove the persistent Pan tool and `H` shortcut, and temporarily replace the Select arrow glyph with Hand only while a valid Space gesture is active. Holding Space before text editing begins disables node dragging/selection and enables primary-button canvas panning from blank canvas or over node content; the cursor becomes grab, active dragging shows grabbing, and release or window blur restores the normal pointer. If an input, textarea, select, or content-editable surface already owns typing focus, Space remains a normal typed character and cannot start panning; Escape or blur ends that typing focus, after which a later Space press may pan. The middle mouse button still pans from blank canvas or over node content without changing tools, shows `grabbing` for the full press, and restores the prior cursor on release. Its active override remains globally authoritative across every canvas descendant and outranks node, control, Frame, edge, and corner-resize cursor rules. Release cleanup runs in capture phase so React Flow cannot swallow it, and pointer cancel, window blur, visibility loss, or a later mouse move reporting no middle button also clears the pan state and cursor immediately. Use `Option +` / `Option -` for zoom and `Z` for Zoom To Fit.
- Opening an existing project must never turn an unavailable or malformed saved workflow into a believable fresh one-canvas project. Load the primary `05. Canvas/workflow.json`; only when that file is genuinely absent may the matching portable `.prismflow` document supply its workflow and asset index. A malformed or unreadable primary save produces a blocking, explicit load error and cannot arm mutation or autosave. No empty fallback may overwrite intact canvas, page, node, edge, or asset data.
- Frame interiors and edges use the normal system arrow even though the Frame remains draggable. Only the four selected Frame corner controls resize: top-left and bottom-right use the northwest–southeast resize cursor, while top-right and bottom-left use the northeast–southwest resize cursor. Frame edges never expose horizontal or vertical resize hit areas. Active middle-button panning still overrides every Frame cursor with `grabbing` until release.
- `Command G` toggles a true node group: grouping two or more selected nodes gives them one selection and movement identity, selecting any member highlights every member, dragging any unlocked member translates every unlocked member by the same delta, and invoking it from any grouped member ungroups the entire group. Expose the same contextual Group/Ungroup action on node and multi-selection right-click menus; Create Frame remains a separate action.
- Every automatically created node—including quick-connect, Export/Route, semantic/starter workflows, connected helpers, generated outputs, and duplicate actions—must use collision-aware placement. Find the closest clean local pane surrounding the anchor according to the live overall node field. Before opening a generic pane, find the nearest existing node column on the correct flow side; if a clean adjacent slot exists above or below that peer, inherit its exact left edge. Weight upstream dependencies toward the complete left-side band—direct-left, upper-left, then lower-left—before directly above or right when their graph-expansion cost remains reasonable; mirror that weighting toward the right-side band for automatically deployed downstream nodes. A user-dropped connection keeps the user's exact drop pane. Direction is a strong visual-flow weight, not an unconditional side lock: graph expansion and distance may overrule it when that band is genuinely unsuitable. Keep a natural 32–45px gap, accept an already-valid nearby slot instead of jumping an entire placement ring for a few pixels, and never stack a newly created node over an existing or simultaneously created node. Collision geometry uses the node's real initial visible state rather than a possible expanded editor height: a compact Browse-state Storyboard is measured as compact. An automatically deployed dependency must stay beside its target instead of creating a long cross-canvas edge.
- Top-bar Add Node places the new node—or the complete linked Style + Storyboard pair—around the current visible flow-space center. Never use fixed world coordinates that can create a second off-screen cluster, and never automatically Fit Everything after insertion when the new node is already visible.
- Conservatively repair persisted coordinates created by a known auto-layout bug only when an auto-linked Style–Storyboard pair is implausibly far apart and its intended adjacent slot is empty. Never normalize ordinary user-positioned layouts or move a naturally spaced pair.
- Top-bar panels such as Assets are true toggles: clicking the active button again collapses its panel. Assets and the node Options sidebar are mutually exclusive while preserving the selected Options node: opening Assets temporarily hides Options; collapsing or re-clicking Assets restores it; clicking a node gear closes Assets and shows Options; toggling that same Options gear closes Options. Opening one top-bar panel also closes mutually exclusive panels such as History.
- Canvas Assets animates in and out as a reserved workspace column, never as an overlay over usable canvas. Its transition resizes the live React Flow viewport so the bottom-right zoom controls and minimap move inward with the visible canvas edge. The bottom Page dock remains horizontally centered within the currently visible canvas and uses equal top/bottom padding for true vertical centering.
- Ordinary materialized Image, Video, Upload, and Output media preserves its natural rendered aspect ratio: the terminal media wrapper owns only the matching bottom-corner radius and `overflow: hidden`, while an image renders at `width: 100%` with automatic height and video follows equivalent aspect-preserving geometry. Never force these ordinary terminal regions to 16:9, stretch media to `height: 100%`, remove Output rounding, or clip the whole node shell. Fixed or selected ratios remain valid only for explicitly designed stages such as generators, Storyboard output layouts, Gallery thumbnails, and reusable framed previews.
- Connecting any concrete Image media output to a Video Generator prefers `Reference Image` over `Starting Image` when both sockets are valid. Image Generator `Image Reference` remains the semantic reference socket. Provider-specific Start/End Frame paths remain available as explicit choices and compatibility validation remains authoritative.


## Ordered semantic inputs — 9 October 2026

The user's ordered pipeline supersedes earlier creation-only input restrictions: Character accepts optional Style, one Wardrobe, and typed Prop (`element-in`) inputs; Location accepts Style, Character, and Prop inputs. Wardrobe/Element remain independent materialized assets. Their lineage flows through Character → Location → Storyboard → Video Generator without creating another cast member. Central `nodeInputPorts` and `connectionCompatibilityError` continue to own menus, drag compatibility and cardinality.

Audio, like video, can pass through Router. The outer Video Reference or Audio Reference socket owns its final motion-camera/audio-timing domain. Generation rejects a persisted Router whose declared type disagrees with its upstream signal; reconnection/hydration may update the derived type before execution. `combinedNodePipeline.test.ts` combines every current Add Node palette kind and keeps terminal/annotation nodes outside provider conditioning.
