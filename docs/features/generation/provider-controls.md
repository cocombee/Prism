## Generation controls and providers

### Service account profiles

- Every service uses the same account-profile manager. Opening one expands it across the full directory width; clicking elsewhere collapses it and restores the two-column layout.
- The first connected profile becomes Default. Default and This Project are independent confirmed buttons with green selected states, hover labels, and explanatory tooltips.
- Projects without an explicit choice follow the current Default; This Project persists an override for that project only and confirmed deselection returns it to Default.
- Account names are local, consistent, sequential `Account 01`, `Account 02`, and so on. Pencil-click and double-click use the Canvas inline rename pattern; account, Canvas, and Project pencils appear only while hovering the name.
- Disconnect blocks use without removing the encrypted key. Reconnect only lifts that blocker and performs no provider lookup. Sign Out removes the key but keeps the row; Delete removes both after confirmation.
- Connections does not query provider identity, billing, balance, or credit. Prism never estimates, invents, or unevenly displays provider credit.
- Missing project access leaves Run clickable and red; activation opens provider/model-aware guidance over the already-open Connections surface.

- Keep node controls minimal and inline; generated output occupies the node stage itself. A run never spawns duplicate Output nodes. Node stage aspect ratio changes with the selected output ratio.
- Generator batching and List use one synchronized contract. `xN` means N expected results; when one List is directly connected, it shows N pending type-aware media boxes in that single node and replaces them in place as results complete. Changing generator quantity updates pending boxes, while List `Add Output` or removal of the last empty pending box updates that one generator within its actual maximum. Quantity reduction removes only excess pending slots; completed media remains preserved. Multiple upstream generators aggregate without bidirectional bulk mutation. At `x1`, the generator still renders its primary result internally and a connected List retains one mirrored box plus Add Output. Without a connected List, quantity never creates one automatically.
- One universal generator output is destination-aware. Existing ordinary downstream media inputs receive only the currently selected carousel result and remain connected when quantity changes. A List connection receives the full generated batch. Carousel navigation is bounded: the first result cannot move backward to the last and the last cannot move forward to the first, including keyboard and full-viewer navigation. Every generated result owns an independent editable media name derived from its managed filename without exposing or editing the encoded extension. The visible generator `@tag`, connected-tag activation, request reference name/tag, URL, path, type, and model all resolve from that same selected result. Switching results leaves the physical edge connected but makes an old result's authored tag ordinary text and activates only the selected result's tag; switching back restores it. Renaming edits only the selected result and its managed physical file. Reusable Character, Element, and Location continue to use their selected reusable identity, while Style remains stable and is never selection-renamed by generated media. Selecting another generator result updates the primary output path used by ordinary downstream edges; quantity changes never silently reroute those edges.
- Ratios must include every value actually supported by the chosen model. Never collapse to a generic three-item set.
- Treat each provider ratio enum literally: `4:3`/`3:4` support does not imply `3:2`/`2:3` support. Image menus must expose both `3:2` and `2:3` wherever the selected image endpoint supports them, while video menus must never submit a ratio absent from the selected video endpoint's schema.
- Keep the selected model readable in compact nodes. Shared control groups build active controls from the exact model capabilities, evaluate semantically valid ordered 2- and 3-row assignments, and prefer fully readable model-default values before minimizing truncation and balancing rows. Never hard-code model-specific row counts or fixed 4/5, 4/6, or 5/5 templates. Large model menus remain independently wide, readable, grouped, and vertically scrollable rather than inheriting the compact closed-trigger width.
- Provider identity is a global rule, not only a model-menu rule. Wherever an AI company or provider is named—including model menus, selected controls, Connections, tabs, cards, badges, status messages, and errors—show that company's recognizable logo beside the name. Model controls specifically show the actual model maker's logo rather than the broker's logo. The shared selector centrally fills missing model-brand metadata and reserves one identical logo column in triggers and rows. Group headings use plain service names and never add `Via` or `Direct`. Never use a generic sparkle, glossy emoji, unrelated symbol, or competing availability dot as identity. Connection/access state belongs to the Run control, disabled state, and tooltip so it does not compete with the green ready action.
- Video duration, frame rate, audio, loop, start/end images, image-reference budgets, and other controls are dynamic per provider-effective model. Renderer readiness and Electron-main submission validation must derive the same budget, identify it as belonging to the selected model, and never silently truncate references. A Multi Character remains one logical UI asset: its editable originals privately compile on every save into one hidden high-resolution sheet, the previous derivative is replaced, no derivative appears in user-facing asset surfaces, and only that single compiled image is submitted downstream. A Single Character sends only its saved Face image and never manufactures a sheet or missing angles; stored Multi views remain available for lossless switching and future recompilation. Auto means provider/model native behavior.
- Image Generator's visible Image Reference port uses that same exact endpoint budget. Current verified edit limits are GPT Image 2 Edit `16`, Seedream 5.0 Pro Edit `10`, Nano Banana Pro Edit `14`, and single-image FLUX Kontext Pro `1`; both Canvas connection cardinality and provider request validation must agree. An unrelated one-image default may never hide capacity supported by the selected endpoint.
- Clarity Image Upscaler exposes its real attribute-only contract: required Image To Upscale, scale, creativity, resemblance, sampling steps, optional negative prompt, and seed, with no prompt field or Prompt socket. RealESRGAN Video Upscaler exposes required Video To Upscale plus scale and never receives Clarity-only fields. Every visible value must appear in the internal request audit and exact Electron-main fal payload; model switching changes typed input/output and clears incompatible stale results.
- fal.ai image routing uses one provider-effective decision shared by execution, pricing, inspector, and internal request audit. Nano Banana Pro text-to-image uses `fal-ai/nano-banana-pro`; image editing uses `fal-ai/nano-banana-pro/edit` with required `image_urls`. Any reference-capable Image Generator exposes the complete supported fal catalog—Nano Banana Pro Edit, Seedream 5.0 Pro Edit (`bytedance/seedream/v5/pro/edit`), GPT Image 2 Edit (`openai/gpt-image-2/edit`), and FLUX Kontext Pro—with each actual model-company logo. Preserve an explicit selection and submit its exact provider-native image schema and endpoint-specific input limit; these models are not Character-completion-only. FLUX Kontext remains a valid single-source route and consumes its primary source. Never offer an edit endpoint without an image, submit another model's fields, force Nano Banana merely because a reference is present, or silently display/estimate a different endpoint from the one actually called.
- A fal model route returning `Billing hard limit has been reached` does not prove the authenticated fal account has no prepaid credit. Immediately reconcile that cached failure against `/v1/account/billing?expand=credits`; a positive live balance clears the account-wide block while preserving a route-specific error on the failed node. Connections refreshes and displays the authenticated fal username and live balance, making a personal/team-key mismatch visible without exposing credentials.
- Image settings follow the provider-effective endpoint rather than the presence of a wire. Nano Banana text and edit modes expose their supported ratio/format, resolution, safety, web-search, and seed controls; FLUX Schnell exposes its own steps, acceleration, guidance, and seed; FLUX Kontext exposes format, safety, guidance, and seed while preserving the source image as primary. Every exposed value is assembled through tested shared payload helpers before Electron main submits it.
- Maintain one audited capability record per exact provider endpoint and mode. Verify all listed variants against current official schemas before release; do not infer Standard from Fast, text from image/reference, or one provider family from another. A selector is enabled only when the endpoint accepts that field. Fixed or provider-native values remain visibly disabled when they help explain the model contract.
- Provider option catalogs are complete for the exact selected endpoint, not hand-picked samples. Every finite enum or service catalog shown as options must contain all currently supported values from the authoritative schema. If a field is open-ended/dynamic and a complete authoritative catalog cannot be fetched, use a validated free-form value instead of a misleading partial selector. Voice language selectors expose every language advertised by the selected model and use its published identifiers; ElevenLabs defaults explicitly to English and has no Auto row or redundant catalog heading, while another provider may expose Auto only when its own API genuinely supports detection. Migrate persisted aliases without sending stale values.
- Every prompt-LLM selector shares one provider/model source of truth across Prompt, Assistant, and Storyboard surfaces. Direct DeepSeek and Moonshot/Kimi connections load and display the complete model list returned by each provider's authenticated Models endpoint. fal.ai may expose DeepSeek R1 wherever its current official schema documents that model; never advertise Kimi through fal.ai until a named Kimi route is verified from authoritative fal documentation. Style remains fal-only under its separate private prompt-builder rule.
- Every logical 2–3-row control group uses one identical external gap for every horizontal and vertical neighbor inside that group. Upper, middle, and bottom groups calculate independently, and their existing inter-group spacing never participates in normalization.
- Closed selector tracks use the exact model/capability state's default selected value measured in actual rendered pixels, including leading company mark, text, chevron, internal gaps, padding, and borders. A later longer selection truncates with `…` and never expands that established default track; the independently sized open menu remains wide enough for full legal options. After tracks are placed, every selector in one row has the same painted distance from its final visible text glyph to the chevron, excluding any leading logo; different rows may use different distances.
- Every side-by-side column or control in one row has the same visible height, enforced by its shared grid/container rather than per-instance margin patches.
- New video generators and model changes default to horizontal `16:9` whenever the endpoint accepts it, otherwise to the first explicit supported ratio or the connected input ratio. Generation duration never defaults to Auto: select the endpoint's minimum valid duration and let the user increase it within the audited limit.
- Character nodes mirror the Style selection pattern: keep the reusable Character picker permanently visible at the top of the node, show an explicit empty state when none exist, and reveal the six-view creation editor beneath it only after Create Character. Selecting any Character from the retained picker immediately collapses the creation editor while keeping its typed downstream edge intact.
- Reusable-library pickers such as Style and Character share the same three-thumbnail rail, drag/wheel behavior, selection border, clipped frame, and full-width Create action. They never show side-navigation arrows or change rail width/padding on hover or focus. Their closed selection state shows no generation prompt, role controls, quantities, Options, or Run controls.
- Character, Style, Location, and Element all use that reusable-library pattern and begin in Browse with an in-node search field above the draggable rail. The empty search shows a purpose-specific placeholder and right-aligned Search icon; typing naturally removes the placeholder and hides the icon. An empty library shows its truthful empty Browse state and compact Create action; it never auto-expands the editor. Character, Location, and Element have no inbound Prompt/Image sockets; each has exactly one optional typed Style input for creation/completion. Their Create editor reveals reference intake, plain prompt-first creation, and generation inside the same node, with exactly image-model, Save, and circular red Play in the footer. Save supplies the asset name and writes to the current project library. Every full-width `Create Character`, `Create Style`, `Create Location`, or `Create Element` action is evenly inset on all four sides within its darker library footer region and never touches, overlaps, or bleeds beyond that region. Remove the obsolete semantic type/name/+ strip entirely.
- On Home, the indented Assets submenu uses regular `400` weight throughout and ends with Favorites after Audio. Favorites is not a peer top-level section. Remove Uploads entirely because Imported already exists as an Assets source filter. Keep Trash separate. The Home header shows project name and counts only; never expose the project filesystem path or the internal `Working file` path there. In the Canvas Assets panel, horizontal grab-drag captures on pointer-down and follows pointer distance one-to-one without smooth-scroll interpolation or simultaneous native horizontal panning; retain wheel and trackpad scrolling.
- Element creation mirrors Character's missing-view discipline with four mutually exclusive, non-numbered slots in exact strongest-to-weakest order: Three-Quarter, Front, Side, Back. Three-Quarter is the mandatory first identity anchor and may be uploaded or generated from `Describe the element to create…`; every other slot stays visibly locked and rejects alternate import paths until Three-Quarter exists. With no Three-Quarter, Play creates only Three-Quarter from the prompt plus optional Style. After Three-Quarter exists, Play means Complete With AI and fills only empty slots inside the same Element. Save requires Three-Quarter. Supplied views remain locked identity evidence, one source image never occupies two angles, and visible geometry, materials, markings, proportions, and construction remain authoritative over text or Style.
- Face is the mandatory first identity anchor for saving a Character manually or completing missing views with AI. Only the non-numbered Face slot is initially available; every other Character view stays visibly locked and rejects alternate import paths until Face exists. Character has an in-node `Describe the character to create…` field and exactly one optional typed Style input, but no generic Prompt/Image canvas sockets. With no Face, Play creates only Face from that prompt plus optional Style; after Face exists, Play means `Complete With AI`. Put `Face Required` inline in the header and change it to `Ready` when supplied; never repeat `Reference ready` below the editor. AI completion is optional. Character and custom Style share a bounded footer with exactly three actions: AI model, Save, and circular red Play. The selector chooses only the image-rendering service/model while a versioned, embedded Sol xhigh identity prompt governs completion and remains absent from UI, exported metadata, and editable prompts. Save asks for an in-app Character name, canonicalizes it to lowercase dash-separated format, and writes the reusable Character into the current project. Completion generates only absent views, stores them back inside the same Character node, and never creates a separate generator/output node. Character has no quantity stepper, semantic type/name footer, Options button, permanent narrative role, or physical attributes. The collapsed Character thumbnail presents its available views as one contact sheet without discarding the individual source files.
- Custom Style creation builds reusable prompt wording, not an image. User text is required and defines intent; its reference image is optional visual evidence. When they disagree, the image is authoritative for attributes it visibly proves—medium, rendering, palette, lighting, texture, lens, and finish—while text remains authoritative for intent the image cannot prove. Play builds or refreshes the finalized subject-agnostic Style instruction and never generates a Style image. Image-only and unprocessed text drafts remain incomplete. The Style footer mirrors Character with fal.ai prompt-model selection, in-app Save, and circular red Play; fal.ai is the only/default prompt-building connection and securely routes the chosen text model through `fal-ai/any-llm`. Do not expose separate direct Claude, Gemini, or GPT connections inside Style. Save asks for an in-app name and writes the finalized prompt to the app-wide private Style library, never the project folder or Finder. Finalized prompt-only presets are valid. Direct OpenAI and Gemini connections remain available only on generator surfaces where those providers offer an actual supported generation endpoint.
- Reusable dependency readiness is global. A connected Character without Face, Element without Three-Quarter, Location without one image, or Style without a finalized reusable prompt keeps its otherwise type-compatible edge red and blocks every dependent downstream Run, including through pass-through nodes. The target Play tooltip names every unfinished `@asset` and exact remedy. Red means compatible but incomplete; an incompatible socket pairing is rejected rather than drawn red.
- Reusable-node headers expose that same single readiness truth before the user attempts a connection. Character shows `Face Required`; Element shows `Element Required`; Location shows `Location Required`; and Style shows `Style Required`. Storyboard uses the same header pill for `Style Required` and `Connected`. Every right-side header reminder uses one compact pill shape, type scale, radius, and alignment: required/incomplete is outline-only with no fill, while Ready/Connected uses the restrained semantic fill. `Ready`, `Connected`, and all required labels use the same exact `25px` height, vertical centering, horizontal padding, type, radius, and header alignment; only text-driven width may differ. Storyboard inherits the shared readiness component directly: its generic header-button selector excludes the readiness pill, and no Storyboard-local size, font, padding, or state-color override may diverge from the global component. Preserve the accepted extra `2px` top and bottom breathing room globally. Each changes state only when the exact source contract used by red-edge rendering and downstream Play validation is satisfied. Never infer header readiness from a separate cosmetic flag.
- The Character selector and the Assets surfaces share one typed project-asset source of truth. A project image typed as Character must immediately appear in the selector; selecting Create Character must not make a previously imported character disappear. An imported Character portrait without explicit view metadata is treated as the required Face when adopted by the Character node.
- Character starts in Browse and exposes no inbound Prompt/Image connector because identity-sheet prompting is internal. It accepts exactly one optional typed Style input for creation/completion rendering language and exposes its typed Character output. A versioned, embedded high-reasoning identity instruction defines consistency and required views; the visible provider/model selector chooses only which image model renders that instruction.
- Horizontal libraries and slider-like rails use wheel/trackpad scrolling and direct grab-drag interaction without rendering a visible scrollbar track or thumb. This applies globally to Character, Style, asset-type, page, and preset rails.
- Reusable Character, Style, Element, and Location library rails never show Previous/Next carousel arrows. Keep the rail at one stable full width on rest, hover, and keyboard focus; never shrink, shift, or add side padding to reserve button space. Wheel, trackpad, and direct grab-drag scrolling remain available without a visible scrollbar.
- Every generation Play action is a circular red control in ready, blocked, incomplete, disconnected, and limited states. Every Play control uses the one global standard diameter; nodes and footer variants must never override it. Enforce equal width and height, matching min/max dimensions, zero padding, fixed flex-basis, square aspect ratio, and a 50% radius so layout pressure can never turn it into an oval. Disabled states remain recognizably red with a not-allowed cursor. Hover must never show a loading/wait cursor; loading visuals appear only after an actual run begins.
- Every Play control always has truthful state presentation. Ready Play is green; active Stop is red with one filled rounded square and no inner ring; completed Rerun is purple with the shared standard single-arrow clockwise Rotate icon. Generated-result presence is the durable Rerun truth: if a prior image, video, audio, or compiled Storyboard result remains preserved in the node stage, a later failure, Stop, idle transition, reload, or reset may change status messaging but may never replace Rerun with Play. Apply that same result-derived action state and exact shared glyphs to the node footer, hover toolbar, Options footer, readiness tooltip, semantic completion actions, and Storyboard compile control. Its explicit button hit target stops pointer-down from becoming a Canvas or node drag, so footer, hover-toolbar, and Options Rerun controls remain clickable. A ready or completed hover tooltip contains only the estimated cost, or exactly `Estimated cost unavailable` when no reliable provider estimate exists—never redundant Run/Rerun narration. Blocked, incomplete, disconnected, access-limited, and provider-error tooltips still state every exact node/model-specific reason and corrective action derived from the same resolved provider-request contract used to run the node. When queued/running begins, apply a clearly noticeable breathing purple halo around the complete node border and replace hover help with a persistent, viewport-level estimated-generation-time-left tooltip anchored to the action. The node retains exactly its normal single border: never add or animate an outline, second border, or bordered outer ring. Only a soft borderless shadow behind the node expands and retracts. Never apply the generating shadow/filter to the React Flow wrapper because that also illuminates ports, the asset tag, and the hover toolbar. Keep the toolbar hover/focus-only even when its node is selected or generating; selection alone never pins top icons open. Keep the countdown visible without hover until complete, error, or Stop; those terminal states remove it immediately. Count down from a configuration-aware estimate and switch to `Finishing… · estimate exceeded` at zero rather than displaying negative or fabricated precision. Persist the estimate shown at request start with actual elapsed timing evidence. If the latest matching completion exceeded that shown estimate, the next matching estimate must be no lower than observed elapsed plus a safety buffer. Custom tooltip delivery belongs to an enabled wrapper and is never clipped or canvas-scaled inside the node. The node Options sidebar footer remains a compact status-pill-shaped action containing the matching icon plus `Run`, `Stop`, or `Rerun` and follows the same color, cost, countdown, and terminal-dismissal states. A generation-capable API-scoped fal key may fall back to a narrowly audited official public price only when the live pricing endpoint is unavailable or omits that exact route; Nano Banana Pro text/edit is `$0.15` per 1K/2K image, `$0.30` per 4K image, plus `$0.015` once per web-search request. Never invent fallback pricing for an unaudited endpoint.
- Any global flat-design rule that removes decorative shadows must exclude the inner `.is-generating` Studio/Storyboard node. A universal `box-shadow: none !important` that wins over `node-generating-halo` is a regression even when the correct queued/running class is present.
- The breathing halo's accepted maximum is `0 0 25px 7px rgba(155,96,255,.406)`, exactly `70%` of the prior `.58` maximum; its minimum is exactly `20%` of that visible intensity, and the full cycle lasts `3.1s`. Keep one fixed shadow on an inner-node pseudo-layer anchored at `inset: 0`, exactly on the node border where the earlier animation's minimum boundary began; fixing it at the expanded maximum endpoint leaves an always-visible outer band and is a regression. Animate compositor-friendly opacity only. The inner edge/limit never moves: scale, inset, geometry, blur, and spread animation are prohibited. Full-node shadow repainting makes the Canvas lag and is also prohibited.
- Generation controllers, subscriptions, and provider callbacks are process-scoped. When a project is hydrated into a fresh Electron process, every persisted `queued` or `running` node is an orphan unless a separately persisted resumable provider request exists. Reconcile that state immediately to a clear interrupted error, clear its progress/countdown, mark an interrupted sequence shot failed, and preserve all prior media and generated-result metadata so the visible action remains Rerun. Never restore `Generating…` or `Finishing…` from workflow JSON when no live controller is attached.
- Installing or refreshing Prism Foundry never changes a saved local project. A provider completion is a real persisted Canvas mutation even if autosave already checkpointed that run as `running`; it must immediately return the header to `Unsaved`. Before orphaned-run recovery can write anything, reconcile the node's exact persisted `runStartedAt` against completed History entries whose managed output files still exist, append only results created by that run, select its latest completion, and durably repair both primary and portable workflow documents. Never use general History reconciliation that could restore an intentionally deleted older result. When a result is deleted while a provider call is still pending, completion merges only the new provider batch into the live current result list and may never write the stale run-start snapshot back. Every hydration prunes missing managed generated-result paths across active and inactive Canvas/Page snapshots and repairs both documents; external legacy paths are not pruned merely for being outside the managed project root.
- Every icon-only, ambiguous, disabled, or state-dependent clickable button has its own action-specific custom tooltip on pointer hover and keyboard focus. A button whose visible wording already explains its complete action needs no tooltip; never repeat the same wording just to satisfy a count. When help is required, native `title` or `aria-label` alone is not the implementation. Route it through the shared viewport tooltip layer, including disabled controls, so it remains unscaled and unclipped everywhere.
- Every tooltip-bearing tool with an assigned keyboard shortcut appends the macOS-facing shortcut in square brackets and declares matching `aria-keyshortcuts`, such as `Zoom In [⌥+]`, `Zoom Out [⌥−]`, and `Fit View [Z]`. Do not invent shortcuts for tools that have none, and do not use middle dots as shortcut separators.
- The same action uses the same shared control everywhere. Every visible Options action uses only the standard gear glyph in one circular control with identical dimensions, border, radius, icon scale, custom `Options` tooltip, and `Node Settings` accessible name. Never render a visible `Options` word inside node footers.
- Video Generator uses the shared fluid control-group allocator. Model remains top-left; Settings stays immediately left of Run/Rerun; Run/Rerun remains bottom-right. Duration, Resolution, Aspect Ratio, Quantity, Motion FPS, optional provider-native Bitrate, and Sound preserve semantic order while reflowing across the optimized 2–3-row model-specific assignment. Bitrate appearing or disappearing triggers a stable recalculation; no fixed top/bottom grid template or hard-coded row count may return.
- Native FPS and Motion FPS are separate concepts on every Video Generator. Native FPS means the real encoded provider frame rate and remains capability-driven; do not simulate a number when it is unknown. Motion FPS means perceived movement-update rhythm and offers exactly 12, 16, 24, 25, 35, 50, and 60 fps. The shared selector menu shows a purple `Native FPS` title first, followed by its actual `24 fps`-style value or the compact value `Native` when undocumented, then a purple `Motion FPS` title and the filtered visual choices. Never show `Provider Native`; the group title already supplies that context and the longer phrase truncates in the accepted compact trigger. Numeric values use lowercase `fps`; only the two titles capitalize `FPS`. If Native FPS is known, remove every Motion FPS equal to or above that rate; if it is unknown, keep the complete catalog and explain the limitation honestly. Motion FPS becomes one provider-effective held-pose/frame-update instruction while preserving native encoding, duration, and playback speed, and must arrive exactly once through deep linked workflows.
- No row, column, selector, menu, button, label, or generated state may enlarge or bleed beyond its owning node/window. Every nested layout uses `min-width: 0`, a shared gap token, content-aware columns, internal clipping/truncation, and aligned left/right bounds; preserve readable controls by reflowing rows rather than widening the frame.
- Make the selected video model's input contract visible in Settings. Start/End Frame controls appear only for image/first-last-capable models; text, reference, and extend modes must plainly state their accepted inputs so capability-driven omission never looks like a missing feature.
- Include only real services/models available from connected providers. fal.ai is the broad generator route; direct OpenAI, Gemini, Claude, Fish Audio, and future connections can expose their own supported capabilities. Direct OpenAI image-edit requests encode every connected input under multipart `image[]`, even when only one reference is present; a scalar `image` field is invalid for this integration and must remain regression-protected without billing.
- Connection status may show connected/credit-required/access-unavailable states only when the provider API can verify them. Do not claim remaining quota when it cannot be retrieved.
- Provider credit, permission, or availability problems disable the billable Run/Compile action, not model browsing. Every model selector remains operable so users can inspect and choose another target; its tooltip may explain the access state without locking the selector.
- Developer-only request audits enumerate every selectable provider-effective option across Image Generator, attribute-only Upscaler, Video Generator, ElevenLabs/Fish voice, and Sound Effects. Every model/route selection and model-specific control must survive from node state into `GenerationRequest` and the provider-effective X-Ray exactly once, including negative prompt, safety tolerance, auto-fix, native/motion FPS, audio, bitrate, interpolation, sampling, guidance, acceleration, seed, voice continuity, and output format. The complete option matrix runs with the fifteen-level valid linked request and hidden wrong-typed-edge audits. This diagnostic remains non-billable and absent from production UI. Image Editor is consolidated into Image Generator with non-destructive legacy migration; Music Generator is retired and cannot be created or run.
- End-stream video audits use multiple model-valid graphs rather than inventing an impossible universal endpoint. The maximal Seedance graph covers Prompt through fifteen typed Routers, Character, Element, Location, Style, one unified compiled Storyboard, generated/uploaded/upscaled image Lists, generated/uploaded video Lists, and Voiceover/Sound-Effects/uploaded-audio Lists. The maximal Kling graph separately covers locked start/end frames and video elements. A compiled Storyboard contributes its structured panel prompt and actual single-image sheet; that sheet is prioritized inside provider reference budgets and is an editorial/continuity/composition map whose panels become separate clean full-screen shots, never a rendered contact sheet. Motion-video references control camera path/timing only, audio references control sound/timing only, and appearance references cannot silently overwrite other domains. Developer tests compare the exact provider-effective prompt with the Magnific contract and preserve authored reference authority, camera/lens/light, causal state ledger, screen direction, final acceptance, and hard avoids exactly once without generating or billing.
- Prompt Enhance belongs inside the Prompt node as a highlighted switch in its header. When enabled, reveal a compact bottom row for supported enhancement models; do not create an Assistant node or giant modal.
- Do not show stale quota errors before the user invokes Enhance. Close transient popovers/modals when navigating away.
- Use recognizable service logos consistently; when an official mark is unavailable, use a restrained labeled fallback rather than pretending a generic icon is the provider logo.
