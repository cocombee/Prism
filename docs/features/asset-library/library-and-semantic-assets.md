## Asset information architecture

- Asset categories are All, Characters, Elements, Locations, Styles, Storyboards, Images, Videos, and Audio. Show every category in Home and the Canvas Assets sidebar.
- Give every managed asset one hidden canonical category. Tabs only filter that category and never overwrite it. Existing project assets and `.prismasset` imports retain their embedded category even when dropped or chosen from the wrong tab/node; route them to the correct category and compatible node automatically. Ask for classification during intake only for genuinely untyped raw media, because pixels alone cannot reliably distinguish a character reference from a visual style.
- Ordinary Image, Video, and Audio imports normalize the visible basename and real managed filename to Unicode-normalized lowercase immediately, including `.PNG` → `.png`, `.JPG` → `.jpg`, and `.MOV` → `.mov`. Apply the same reconciliation to dialog import, dropped paths, portable-package import, registered-source return, asset relist, relink, and rename. Never transcode bytes. Case-only filesystem changes use a temporary managed filename, and collisions receive deterministic suffixes.
- Registered/relisted casing repair and ordinary rename are one rollback-capable transaction across the physical managed file, asset index, canonical workflow including every page/canvas copy, generation history, asset URLs, and portable project document. On any write or rename failure, restore every JSON document and physical path before surfacing the error. Rename fields hide the real extension and the main process always reattaches the unchanged encoded extension.
- Make the Canvas sidebar category rail horizontally scrollable when it does not fit. Support horizontal trackpad/swipe, ordinary vertical-wheel translation, and direct grab-dragging. A normal press on any category chip always selects it; do not capture the pointer or cancel its click for incidental movement below the deliberate eight-pixel rail-drag threshold. Keep its scrollbar track and thumb invisible, and keep filtering directly beneath it.
- Use category-specific empty states and creation routes. Do not show inherited dummy assets in a genuinely new project.
- Asset cards support search/filter, rename, favorite, show in Finder, lineage, relink, trash/restore, and applicable export. Prefer Show in Finder over a redundant download action.
- Characters use nine identity views in this exact priority: Face/front, Right Three-Quarter, Profile, Full Body, Back portrait, Smile, Left Three-Quarter, Side Body, and Back Body. Smile remains because natural teeth, lip shape, and expression asymmetry are identity evidence. Face is already neutral, so never add a separate Neutral slot. Right Three-Quarter and Left Three-Quarter are true opposite 45-degree yaw views: both eyes remain visible, the far cheek is visibly foreshortened, and neither result is near-front or near-profile. Profile faces left. Side Body is a true full-body side profile, and Back Body is a straight full-body rear view. Apply this exact order and direction contract to visible slots, direct drops, manual intake, AI completion, and provider reference preference. Face remains the sole required anchor; after Face exists all remaining views become manually available together rather than adding sequential lockouts. Create Using Prompt and Create Using Reference each instantiate only the Character node and open its in-node editor; they never scaffold a separate Prompt or Image/Upload node. Reference files and Canvas Image assets drop directly into the chosen view box.
- Character completion remains available until all nine distinct view IDs exist; a legacy six-view Character is incomplete and must expose completion for Left Three-Quarter, Side Body, and Back Body. Under fal.ai, the completion selector includes the provider-native Nano Banana Pro Edit, Seedream 5.0 Pro Edit (`bytedance/seedream/v5/pro/edit`), GPT Image 2 Edit (`openai/gpt-image-2/edit`), and FLUX Kontext Pro endpoints, each with its exact request schema and actual model-company logo. Once Face exists, the completion action uses the shared Rerun glyph rather than Play.
- Every Character completion request carries the exact assigned panel geometry plus all supplied and earlier same-run completed views as cumulative negative evidence. Profile is a true 90-degree left-facing silhouette with only the near eye visible; the two three-quarter panels are opposite 45-degree yaw views; rear and full-body panels retain their explicit 180/90/0-degree geometry and complete crop. Never recreate, copy, or mirror another assigned panel. Smile is the deliberate same-axis exception: it shares Face's frontal camera axis but must remain visibly distinct through its natural smile, teeth, lip shape, and expression asymmetry. Before accepting a result, require the assigned view to be identifiable from eye visibility, silhouette, shoulder direction, crop, or expression without relying on its label.
- Elements are one reusable four-view identity set ordered strongest to weakest as Three-Quarter, Front, Side, Back. Three-Quarter is the sole required anchor and may be imported or generated from the in-node prompt; two or three supplied sources may strengthen identity. One source file can occupy only one angle, and Complete With AI creates only missing angles without replacing, mirroring, or regenerating supplied views. Empty Character and Element/Product view slots show approved project-owned transparent, low-opacity, line-only, no-fill simplified 3D surface-mesh artwork appropriate to the exact view, behind the existing plus or lock icon. Character uses nine high-resolution artworks for Face, Three-Quarter, Profile, Full Body, Back, Smile, Left Three-Quarter, Side Body, and Back Body. Element/Product uses four distinct recognizable teapot artworks whose Three-Quarter, Front, Side, and Back geometry is actually angle-correct, with contour loops and longitudinal mesh lines. Framework images contain real alpha with no baked checkerboard. Optical calibration happens at the final slot size: tall full-body source strokes are thickened enough to match the perceived line strength of portrait meshes when both are fitted inside the 104px frame. Measure and size them from perceptually visible mesh pixels—not the original transparent canvas, invisible padding, or barely visible alpha residue. Each approved PNG is tightly cropped to those visible bounds with a small safety margin. Judge relative size by perceived main-body mass body-to-body rather than comparing each image's bounding-box width against height: the approved Teapot corrections are Three-Quarter `0.85`, Front `0.85`, Side `0.95` with the complete right contour visible, and Back `0.90`. Per-angle transforms require explicit packaged visual calibration and may never disguise a duplicated or incorrect angle. Preprocessing removes isolated chroma-key/floating pixels without erasing legitimate mesh lines. Never substitute a stick figure, mannequin diagram, bounding-box cage, decorative icon, generic SVG approximation, or misleading transformed duplicate. The framework is guidance only, never generated content, and disappears when an image occupies the slot. Locations capture only useful environmental facts and may likewise start from an in-node prompt or supplied image. Image, Video, and Audio uploads remain straightforward.
- Portable user assets use `.prismasset`. A `.prismflow` opened elsewhere may report missing media and offer targeted or folder-wide relinking.
- Separate the user-facing asset name from its internal media filenames. A reusable multi-view Character or Element is one named Prism Asset and exports as `<Asset Name>.prismasset`; its Face/Front, Three-Quarter, Side, Back, and other contract-defined views are internal members, not separately named user assets. Never append `.jpg` to the logical Prism Asset name, never force its member images to JPEG, and never invent Left/Right variants that are absent from the node's defined view metadata. Preserve each member's real encoded format internally. A genuinely single-image result—such as a generated background or one Storyboard panel—may be saved as `<Asset Name>.jpg` when JPEG is its actual selected or returned format; otherwise preserve the real extension. A complete multi-panel Storyboard remains a Storyboard asset rather than masquerading as one JPEG.
- The Home card for a reusable Character, Element, or Location acts on the whole collection, never one internal view. Every user-owned Assets card exposes exactly Favorite, Show in Finder, Trash, and More in that order; application-owned or otherwise undeletable assets omit Trash and any destructive action. More contains exactly Export, Rename, and Relink, never Copy Prompt or View Lineage. Export uses the standard upward export icon and visible text `Export` only; the `.prismasset` enclosure name stays out of the menu. For a reusable collection, Favorite and Trash apply to every member together, and Finder reveals the collection wrapper folder rather than selecting a JPEG member. Double-clicking the displayed logical name opens inline rename; committing canonicalizes the name and updates every member's metadata plus every linked Canvas node/reference together while preserving member paths, so rename can never create missing Canvas media.
- Character previews use the Multi contact-sheet frame as the global format in the compact selection rail, Home/Canvas cards, and expanded preview. A saved Single Character contributes its one composite sheet to that same one-cell frame; Multi and legacy Characters use the balanced count-aware contact sheet so the complete available view set remains visible. One image fills the preview; two fill equal cells; four, six, and eight fill complete even grids; odd counts above one omit only the unmatched final member from the preview without deleting it. Show at most eight Multi preview members. Every Character image uses view-aware filling/focal metadata without geometric stretching. Element and Location previews retain the same balanced count-aware grid principle.
- Group Character, Element, and Location members by canonical category plus `metadata.assetName` on every Home Assets view, Canvas Assets view, and reusable-node selection rail, even when legacy or promoted members live in different physical folders. For legacy managed members missing `assetName`, migrate/group by their canonical reusable parent-folder name before falling back to the timestamp-like media filename. Never render one internal member as a separate preset. Saving must update already-managed same-category members in place rather than re-promoting duplicate copies. Resolve Imported/Generated at this logical-collection level before applying the origin filter: an imported anchor completed or otherwise finalized with any generated member becomes one Generated reusable asset containing every imported and generated view, appears once under All and Generated, and disappears entirely from Imported. It must never split into separate imported and generated cards or lose the imported anchor when Generated is selected. An all-imported collection remains Imported. When a generated Image record has been promoted into one of these collections, keep its underlying source file and history record but suppress that duplicate source-media listing anywhere the semantic collection is visible.
- An Assets-card More menu stays open while the user interacts inside it and toggles normally from its own three-dot trigger. Pointer-down anywhere outside the menu and its trigger closes it immediately; Escape closes it too. Opening More must never leave a stale menu floating while the user clicks another control or blank area.
- Every Canvas Assets sidebar row has a real keyboard-accessible selection action across both its thumbnail and name/details region, independent of its trailing management controls. Clicking or keyboard-activating a row selects and visibly highlights it only; it never deploys, opens, navigates to, or focuses a Canvas node. Only native drag-and-drop deploys an available asset on the Canvas at the user's drop point. The row selection action has a custom Canvas-sidebar-only hover tooltip after exactly 1.5 seconds that explains selection and drag deployment; do not impose that delay on the outside Home library or unrelated buttons. Keep `Import Asset` and the category-aware `Create` action fixed immediately below the filters and outside the scrolling asset list so both remain visible while rows scroll. Home Assets and Canvas Assets invoke the exact same shared Import and Create handlers: Create operates on the currently active asset category, while All opens the general Create menu. Import never coerces an ordinary file into the active category: supported raw media is classified from its real MIME type and stored under Images, Videos, or Audio, portable `.prismasset` assets preserve their validated package category, mixed selections route each file independently, unsupported files are rejected, and the library moves to the one real destination category or All for a mixed selection. Character, Element, and Location drops create one correctly typed node containing the complete logical collection; ordinary Image, Video, and Audio create one linked Upload node; built-in or global Styles create the corresponding Style node. A saved Storyboard drop creates a reusable Storyboard instance plus every directly connected reusable Character, Element, Location, and Style upstream dependency and their typed incoming edges, preserving relative layout and remapping the cloned Style's Storyboard link; it never clones downstream consumers or unrelated graph nodes. Creating a new Storyboard also creates and links its required upstream Style. Other asset types never invent or clone optional upstream dependencies. While dragging, show one fixed 1:2 rounded card approximately 20% larger than the accepted sidebar asset row—not a 30–40% enlargement—that preserves the row's actual thumbnail or semantic multi-view tile on the left and its canonical name plus subtype on the right; round the inner thumbnail too, and independently ellipsize both text lines inside the fixed card. Internal drag payloads contain only stable local IDs/keys and resolve against current project state at drop time. Never accept a drop back onto the Assets sidebar itself. A missing media row remains disabled and non-draggable until relinked.
- Inside every node, all text around and below the header—including controls, values, actions, badges, statuses, asset names, and body labels—uses regular `400` weight. The node name is the only semibold text at `600`; no other node text may be bold. The descriptive subtitle immediately beneath every node name returns exactly `2px` to its original compact size without changing the node name. Compact action and status copy such as Add reference, Add Output/Add Media, its secondary helper, Synced with, and the Guide/Auto/Lock fidelity choices returns exactly `2px` to its pre-enlargement size, matching selected model, Quantity/output values, ratio, resolution, Duration, FPS, Sound, Type, and equivalent controls. Every node-local `Describe…` prompt and placeholder also returns exactly `2px` to its original size. Reusable-editor headings such as `Custom Style`, `Custom Location`, and `Custom Element`, and all matching `Collapse` actions, explicitly return to the original compact `8px` size and regular `400` weight. Options always uses the true gear-shaped `Settings` icon and never the sliders-shaped `Settings2` icon.
- Across Home Assets, Canvas Assets, reusable-node libraries, cards, search, tooltips, tags, and rename fields, Character, Element, Location, Style, Storyboard, and every other categorized reusable asset show only their canonical logical asset name. Canonical reusable names use Unicode-aware lowercase words joined by single dashes, such as `yusuf-anaqi`; a node tag is exactly that name with one leading `@`. Cards, libraries, metadata, rename fields, and `.prismasset` export names omit the `@`. Every reusable save, rename, and project-load migration applies this normalization. Never expose an internal member's `.jpg`, `.jpeg`, `.png`, `.webp`, or other media extension as the reusable asset name. Ordinary Image, Video, and Audio imports normalize the complete physical filename to lowercase, including the real extension (`ACTOR-C.PNG` becomes a collision-safe lowercase `.png` asset). All Rename fields seed and edit only the basename, commit the basename in lowercase, and preserve the source media format while normalizing extension case; a format change belongs only to a dedicated conversion/export action that genuinely transcodes the file. Renaming from either a node or Assets surface updates one canonical logical name, all member metadata, every referencing node/tag/library/card, and the eventual `.prismasset` export name atomically; changing only `referenceTag` is a defect.
- Reusable-asset save and rename fields seed from the canonical lowercase logical name, never title-case the first character, and disable automatic capitalization, correction, and spelling decoration. Raw typing stays exactly as entered while the field is open; canonical lowercase dash normalization happens only on Save/Rename commit.
- The reusable pre-save name input uses the nearest smaller shared node-control font token (`--font-node-control`), never an isolated enlarged 11px value.
- Reusable Character, Element, Location, and custom Style editors establish a content baseline after Edit rehydration or after Create initializes its blank form. Merely opening Edit or Create is clean: editor-open flags are transient UI state excluded from project-dirty and Undo fingerprints, so neither the reusable Save nor the project top-bar Save turns red and the displayed asset name remains canonical. Only a real change to authored prompt/style text, provider/model settings, or assigned media/view marks the editor dirty. Dirty Save uses the existing standard subtle-delete red, while the visible tag alone reads `@Unsaved`; internal `title`, `referenceTag`, connections, and logical library identity remain unchanged until a successful Save. Cancel restores the baseline snapshot, a failed save remains dirty/open, and a successful save closes the editor and restores the canonical visible name.
- On project load, if an older persisted semantic node has a user-edited `@tag` that differs from its title (for example `@yusuf-anaqi` beside `Yusuf`), treat that tag as the user's intended logical asset name and migrate it into every matching member's metadata, the node title, all references, and future `.prismasset` export name. Do not migrate tags that still match the title slug or built-in/default tags. This migration must be idempotent and preserve every member's actual filename and encoded format.

- Character preview packing uses only materialized, distinct assigned views. Sort available images by canonical view order, deduplicate repeated assignments, and compact the next available view forward whenever an earlier canonical view is absent; never reserve an empty panel for a missing Right Three-Quarter, Profile, or any other view. After compaction, preserve the established fluid one-image or complete 2/4/6/8 grid rule, omitting only an unmatched odd final image and never deleting it from the asset.
- Character creation exposes two explicitly named persisted modes: `Multi` and `Single`; missing/legacy mode defaults to Multi. Multi retains the complete nine-view workflow, hides the description box, and Play completes only missing panels after a Face anchor exists. Single shows one image slot plus the description box, and Play generates all nine required angles as one composite image. Mode-tagged media is isolated in the editor: a saved Single sheet never appears in a Multi panel, and Multi views never appear in Single. Switching modes may retain unsaved opposite-mode work internally, but Save commits only the current mode and retires/discards the previously saved opposite-mode members. Save promotes raw source media into managed Character storage so deleting the source cannot remove saved Character content; Export wraps the complete managed collection as one `.prismasset`. Rename, export, favorite, delete, relink, grouping, and `@tag` behavior remain one Character asset transaction in either mode.

Semantic promotion preserves source origin at its resolved managed path in the main-owned asset index. Imported semantic references stay imported when copied into reusable collections. Unregistered sources retain generated fallback. Renderer provenance and a matching filename elsewhere cannot change origin; original files/records remain preserved.
