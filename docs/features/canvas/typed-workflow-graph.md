## Typed workflow behavior


- Replace ambiguous colored connector dots with 32px icon ports that identify Text/Prompt, Image/Reference, Video, Audio, Style, Storyboard, or mixed media. Ordinary node hover never reveals unrelated empty ports. Selection or a live compatible connection reveals the relevant painted icons, and the accepting endpoint pops only inside its connection radius. For an ordinarily deployed occupied port, the real React Flow connection anchor shares the painted icon centre so its wire begins behind the icon rather than visibly emerging from the node body. During a live drag, only opposite-direction candidate ports participate in incompatibility hiding; same-direction ports keep their ordinary idle visibility because output-to-output and input-to-input are never candidate connections. When an occupied opposite-direction endpoint is incompatible, smoothly retract and hide only its painted icon; keep its measured anchor and existing wire fixed at the deployed icon centre with no wire-hide animation.
- Every output uses one universal Export/Route icon. Clicking it opens the standard compatible-node picker; dragging it still creates a normal typed edge; dropping on blank canvas opens the same picker at the drop point. Preserve the hidden typed signal and target filtering even though the visual output icon is universal.
- The Export/Route glyph is painted by the real React Flow source `Handle`; React Flow exclusively owns pointer, mouse, and touch down. Prism owns plain click only. Reveal the glyph for node hover, node selection, an occupied connection, and every live-guidance state. Never add a covering hit-area workaround or custom pointer-down handler. Gallery remains view-only and advertises no output.
- Derive generator inputs from the selected model contract. Text-to-video exposes Prompt only; image/reference video exposes Prompt plus Image Reference; first/last-frame video exposes Prompt, Starting Image, and Ending Image; extend-video exposes Prompt plus Video. Do not leave unsupported or invisible-input edges behind when a model capability changes.
- Ordinary imported Image media routes through the shared compatibility preference rather than a local handle list: Image Generator prefers `image-in`; a selected Video Generator model that supports ordinary references prefers `reference-in`; otherwise its declared compatible frame input is used. Enforce the exact target socket cardinality before creating the source node or edge. Explicit Start and End Frame selection remains separate and unchanged.
- Never make Start Frame, End Frame, and independent visual References mutually exclusive at the workflow level. Show separate Start, End, and References ports together. When a requested endpoint cannot accept the combination, route to a connected provider model that can preserve all three (currently Kling O3 Reference for fal.ai), update the displayed model without adding a separate Kling status banner, and keep a request-time fallback for older persisted workflows. Reclaim the removed banner area for the prompt stage through the controls immediately below it. Never silently discard reference media or imply that prompt-only mention equals visual conditioning.
- Every port needs a concise tooltip and accessible label that describes what it accepts or routes. Validate click-versus-drag separately so a completed drag cannot also trigger the picker. The React Flow handle and its painted icon remain coincident 32px circles; bridge the node-to-icon pointer path only with an overlapping transparent pseudo-element that does not participate in handle measurement, because resizing the measured handle visibly detaches the wire endpoint. Once a click opens forward or backward quick-connect, keep only that exact initiating port deployed until the picker completes or is cancelled, even after the cursor leaves the node.
- Starting Frame and Ending Frame use distinct timeline-standard icons, not the generic Image icon. Their real handles remain measured at the outward deployed-icon centre before hover or drag; stowing moves only the painted child inward. Every temporary or completed edge therefore stays anchored behind the outward icon position, and selection or compatible live guidance reveals the painted icon without moving the measured anchor.
- Prompt can feed image/video generators, editors, storyboard text, and compatible text utilities such as Router. It never feeds List, which is media-only. Reusable Character, Location, and Element keep prompting and image intake inside their own Create editor and accept only an optional typed Style canvas input. Style itself remains strictly output-only.
- An empty Media or generated Output node is not assumed to be an image. Its output stays mixed/untyped until a materialized asset establishes Image, Video, or Audio; the visible port, quick-connect targets, drag validation, and internal request audit must all derive from that same live media type.
- Connected semantic assets automatically expose insertable `@tags` and pass concise role-aware references rather than verbose descriptions.
- New semantic assets start with truthful purpose-specific defaults: Character is one portrait-oriented identity, Location is one `16:9` environment, and Element is a square reusable object with four fixed named view slots. Element exposes no quantity or generic angle-count control; its four slots, stored view metadata, completion request, internal audit, and saved asset set must never disagree.
- A deployed semantic node keeps its declared type. Location and Element may be renamed and supplied with guidance, but an inline type selector must never mutate them into Character or Style and leave stale ports, controls, persistence, or generation defaults behind. Use an explicit role/adoption workflow when reclassifying an existing materialized asset.
- Every connected input automatically receives a stable `@asset-name` and a role-specific provider instruction. This includes Prompt, Storyboard, Character, Element, Location, Style, source image, Start Frame, End Frame, image/video/audio reference, Video To Extend, List, and media collection inputs. Derive the final provider instruction from one shared role matrix and insert it exactly once. The prompt autocomplete remains the sole tag-authoring surface: never add a separate connected-tag insertion-chip strip. Show a connected-input row only when the exact connection supports the actionable `Guide | Auto | Lock` fidelity choice; fixed instructions remain provider-effective but hidden instead of appearing as read-only HARD RULE rows.
- `Auto` fidelity is prompt-sensitive per reference. Explicit inspiration, loose-guidance, adaptation, or reinterpretation language resolves to Guide strength; explicit exact, unchanged, unmodified, authoritative, do-not-redraw, or original-layout-intact language resolves to the strongest provider-supported preservation rule; ambiguous language remains balanced Auto. This inference changes only the hidden provider instruction and never rewrites the authored prompt or the visible Auto selection. `Lock` means the strongest preservation request the selected generative provider can honor, never a pixel-exact guarantee. GPT Image 2 already processes every input at high fidelity and exposes no stronger fidelity switch; preserve its anonymous input order exactly with the numbered prompt mapping and disclose in the tooltip that exact text or pixels can still be redrawn.
- A committed rename from a Canvas node, Home Library, Canvas Assets, or the eligible full-resolution viewer is one asset transaction. Ordinary media renames its managed file plus every owning node title, tag, and path, while its Rename field omits the real extension and the main process always reattaches the unchanged source extension. Typing `.jpg`, `.png`, `.mov`, `.mp4`, `.wav`, or another media suffix can never spoof or change the encoded format. Reusable collections rename all member metadata, every linked node/reference, every Library/Assets card, and future export identity. Non-renamable assets—including built-in/application Styles—show no Rename control or editable tag on any surface. Every live incoming row, prompt, selector, and node label must reflect the new identity without stale edge decoration. For legacy persisted sources, treat the canonical `referenceTag`, title slug, and reusable metadata name as graph-backed aliases for active-token recognition and exact tag connection, while suggestions show the current canonical visible tag. In actionable fidelity rows, reserve the right edge for the full `Guide | Auto | Lock` pill at every supported node width. The tag and role use only the remaining left space and independently ellipsize; they may never push or clip the fidelity control. Keep rule prose in the row tooltip rather than duplicating it into the constrained visible row.
- Connected-input tags are authorable through one shared autocomplete editor on Image, Video, compatible reusable-asset prompts, Storyboard panels, and the corresponding Options prompt. Typing `@` filters canonical tags from compatible real Canvas sources; click, Enter, Tab, or completion of an exact available token creates its typed incoming edge exactly once through the central compatibility and input-cardinality validator, adopting the established compatible provider model only when that real port requires it. A source that is already incoming must activate the exact same canonical tag shown above its Canvas node immediately. A token is purple only while its exact canonical source is connected. Disconnecting never deletes authored text—it deactivates the token to ordinary text—and a matching prewritten or previously disconnected token turns purple immediately when that source edge is added or restored. Duplicate canonical tags never select a source by guesswork, and deleting tag text does not silently remove an edge. Suggestions and active coloring must derive live from the graph, never stale persisted decoration. Its transparent native textarea and visible highlighted paint layer wrap against the identical live text-content width: derive textarea text width from `clientWidth` minus horizontal padding after paste/value changes, element or window resizing, and scrollbar appearance; add only the paint layer's own padding/borders, require paint-layer `min-width: 0`, and keep wrapping rules identical. Outer-shell width and `offsetWidth` are invalid. Long pasted prompts preserve exact visible caret, selection, Backspace, and Delete line mapping.
- Canvas paste accepts both macOS `⌘V` and `Ctrl+V` whenever input, textarea, select, or content-editable focus does not own the command. Supported copied image files or OS clipboard bitmaps become managed imported Image assets at the last Canvas pointer position, with visible viewport center as fallback. Preserve original PNG/JPEG/WebP/GIF files exposed by file URL. A raw bitmap fallback is encoded directly as PNG with alpha intact; never composite through a canvas, convert it to JPEG, or introduce a white/black background. A private Prism clipboard marker distinguishes copied nodes from external images; unrelated clipboard text creates nothing.
- Frame-like visual inputs expose a compact per-connection `Guide | Auto | Lock` control. Auto is the balanced default: preserve subject, composition, action, and continuity while repairing defects. Guide treats the input as looser creative or structural direction. Lock routes media through the provider's exact frame/source field and explicitly follows visible pixels and quality. The selection must alter actual request routing as well as the hidden `@tag` instruction.
- Every scrollable connected-input rule list contains only rows exposing `Guide | Auto | Lock`, in stable connection order. Fixed HARD RULE instructions never render as rows. The list's visible overflow track and thumb use the shared slim lightweight scrollbar treatment.
- Character, Element, Location, and Style references must remain distinct provider roles through the final request.
- Storyboard never breaks into a generic List: its ordered panels, timing, camera guidance, and model target remain typed Storyboard data. List exposes one visually universal but internally type-aware media-batch input for Image, Video, or Audio only; it rejects Prompt/text, Style, Storyboard, Character, Element, and Location and never exposes redundant media-specific sockets.
- Validate semantic role before broad media type. Character and Element are References, never Start Frame, End Frame, Prompt, Video, or Audio. Storyboard connects only to Storyboard-aware inputs. Style connects only to Style or explicitly compatible Reference inputs. Audio connects only to Audio inputs, and Video only to Video inputs. Location is the deliberate visual exception: it defaults to Reference but may intentionally serve as a Start or End frame.
- Socket quick-connect is bidirectional and exact: clicking an output offers compatible destination nodes, while clicking an input offers compatible source nodes and connects the newly created source to that precise input. Video Start Frame and End Frame source pickers expose Location as the sole semantic-frame option; Character and Element remain Reference-only.
- Dynamic Image, Video, and Upscaler model changes reconcile every existing incoming edge against the new `nodeInputPorts` declaration before the next request. Preserve an unchanged valid handle. Otherwise, ordinary references may move only to the selected model's current ordinary-reference handle, and semantic Character/Element/Location/Style edges may move only to their matching semantic or compatible generic Reference role. Starting Image, Ending Image, source Video, Storyboard, and other dedicated roles never cross-remap. If no compatible replacement exists, remove the edge with one explicit notice rather than retaining a floating wire on a nonexistent handle. React Flow node internals are remeasured after the port set changes.
- A linked Style is ready only when both its edge exists and it has a selected preset, prompt, or reference. Selecting, prompting, or importing a Style restores its intended Storyboard edge after disconnection. Creating a Storyboard must never open or leave behind a duplicate floating Style picker.
- Style is strictly output-only and has no inbound canvas socket: custom wording and the optional reference image are added only inside the Style editor, while the node exposes only its typed Style output. Character, Element, and Location are the deliberate exception: each accepts one optional typed Style input used only when creating or completing that asset.
- Do not expose permanent narrative-role or physical-attribute fields in the Character asset editor. Character assets represent reusable identity; any future Main, Supporting, or Extra role belongs to the specific connection/use context rather than the global asset.
- Validate the exact source signal against the exact target socket, not only the two node kinds. Image-only sockets reject Video and Audio; Video sockets reject Image and Audio; Audio sockets reject Image and Video. Preserve an incorrectly chosen file safely in the asset library, leave it unconnected, and show a plain-language correction such as `Please insert image-related assets only.`
- A Storyboard has one dedicated typed output and connects directly to Video Generator only. One Video Generator Storyboard socket accepts exactly one Storyboard plan: reject a second connection at drag/quick-connect time and reject persisted duplicates before provider assembly rather than overwriting, concatenating, or displaying two active rules while using only one plan. During saved-graph migration, keep the first edge in stable order, disconnect surplus edges, and show one explicit notice naming what changed. It is reusable structured planning data plus an optional current compiled image, never List or Gallery media.
- List accepts and outputs ordered homogeneous or aggregated collections of images, video, or audio. Gallery is different: it is a clearly labelled view-only terminal for materialized media. Never advertise Gallery as a downstream data List or accept Storyboard/text directly.
- Gallery is non-generative, media-only, and fully inspectable: images render visibly, videos expose playback controls, and audio exposes playback controls rather than an inert icon. Reject raw Prompt/text and text-Router edges before commit instead of accepting a wire whose content Gallery would silently discard. Legacy generated Output nodes remain source-only materialized results with no inbound socket; generated media stays inside its generator and Gallery is the explicit view-only terminal.
- List and Router output ports visibly adopt their derived live signal instead of remaining cosmetically mixed. Router uses its own Link icon rather than List's icon and names the current routed type. No two List input ports may occupy the same position.
- Standardize connection compatibility in one source of truth; never hardcode a different quick-connect list per UI surface.
- Every route advertised by quick-connect must resolve to a real input port and pass the same semantic compatibility validator used by drag connections. Keep an exhaustive source-signal × target-node contract test so UI suggestions cannot drift from runtime ports.
- Validate every reachable upstream edge before any billable request, not only edges entering the final generator. A malformed connection hidden inside a List, Router, semantic asset, or compiled Storyboard must stop the run with the same useful typed error.
- Compiled Storyboard lineage contributes its current shots, connected references, and current Style exactly once. Provider-native per-shot payloads must retain global context and Style exactly once while preserving every shot's duration, framing, movement, and audio cue.
- Non-Seedance provider-effective Video prompts use the production shot specification in exact section order: `SCENE CONTEXT`, `ACTIVE REFERENCES`, `REFERENCE MAP`, `LOCATION MAP`, `FIRST FRAME`, `FORMAT MODE`, `CUT 1..N`, `OPTICS`, `CAMERA`, `PHYSICS`, `ACTION`, `PERFORMANCE`, `LIGHTING`, `AUDIO`, `STYLE`, `POSITIVE LOCKS`. Seedance uses its canonical ordered headings from `ASSISTANT TASK` through `HARD AVOID`, assembled only at provider time. `LENS AND OPTICS` follows the selected Motion FPS and emits one 180° shutter-angle default whose exposure time adapts automatically with cadence; an authored shutter angle or shutter speed overrides it. One canonical asset tag produces one reference-authority line regardless of coordinated view count. Reference descriptions use source `prompt`/`stylePrompt`, never Connected Rule prose or its HARD/AUTO/GUIDE/LOCK labels; every fact has one section owner and may not be repeated downstream. Non-Seedance retains standalone required `REFERENCE MAP`, quantified camera, conditional `PHYSICS`, required Character `PERFORMANCE`, non-echoing `LIGHTING`, and verbatim `STYLE` behaviour.
- When a previously compiled Storyboard has panel edits, preserve `storyboardNeedsCompile` through library selection and show a non-blocking stale-map warning on its downstream route and Run tooltip. Continue using its current text-only shot plan, omit the stale sheet, and never spend against an outdated visual map silently. A never-compiled Storyboard with no sheet remains a normal text-only plan without this warning.
- Full request X-Ray data remains developer-exclusive. The node inspector may show one collapsed, read-only `Composed Provider Prompt` section containing only the provider-bound prompt text, with a copy action and caught assembly errors. A Kling `multiPrompt` renders one numbered entry per provider-native shot instead of a misleading combined prompt. Never expose credentials, broker routes, request-control payloads, binary references, or the complete request object in production UI. Sanitized, non-billable internal tests may continue inspecting the exact route/model, storyboard payload, and submitted controls.
- fal.ai account status never equates billing-endpoint permission with inference permission. The exact billing-only denial returned to a recommended API-scoped key leaves the connection ready with credits undisclosed; credential replacement/removal clears cached provider failures, and only an actual provider-effective run may prove generation access.
- Inspector reference counts and reference-only controls derive from materialized resolved media, never from the raw number of incoming edges. Prompt, empty Style, Router, or other non-media wires must not make the inspector claim an image reference, switch ratios, or display a reference-edit endpoint.
- Required source sockets remain provider-primary at default Auto fidelity. In particular, Image Editor `Source Image` and Image Upscaler `Image To Upscale` must populate the provider's primary image field; only separately connected Reference inputs may trigger a multimodal reference route or model switch.
- Cross-node resolution must remain correct through at least fifteen linked intermediate nodes. Automated internal request-audit coverage must combine typed pass-through utilities, prove each upstream instruction/rule is injected exactly once, and reject an incompatible edge even when it is hidden fifteen levels upstream, before any provider request or credit use.
- Inspect the resolved final request to prove it carries prompt, style, characters, elements, locations, aspect ratio, shot size, duration, camera movement, audio cues, and model-specific options.
