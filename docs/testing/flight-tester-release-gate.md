## Flight Tester release gate

- Treat `/Users/mrkokom/Library/CloudStorage/GoogleDrive-cocombees@gmail.com/My Drive/Hermes/AI Video/Prism/outputs/build/mac-arm64/Prism Foundry.app` only as the internal development Flight Tester runtime, never as the intended user-facing deliverable.
- After each approved implementation change, run appropriate automated validation and refresh only Flight Tester. A valid refresh is a process boundary: fully quit the old Flight Tester before replacing its packaged bundle, package the unsigned runtime, then launch exactly one new instance and inspect bundled images from that process. Never overwrite `app.asar` beneath a running renderer or merely raise/reuse its old window, because stale hashed asset URLs can render broken-image placeholders even when the replacement archive contains every file.
- Existing-candidate inspection exception: when Codex has already built the candidate, inspect that exact `.app` and do not rebuild, repackage, resign, regenerate, replace, launch a second copy, approve, or promote it for the sake of inspection. Record the exact path, `app.asar` hash, bundle identifier/product/architecture, signature result, packaged entry/readback, and the current-Hermes-source comparison.
- Separate static package evidence from visual/runtime evidence. Use isolated temporary user data and a temporary project/fixture, preserve the approved fallback and current Hermes source, and never mutate a user project to obtain evidence. If a native file chooser or foreground approval blocks a requested interaction, do not bypass it; report visual/runtime coverage as incomplete. Missing Storyboard Image Layout UI/CSS is static package evidence, not permission to rebuild.
- Codex build-method assimilation is a separate release gate: preserve the exact parent/checkpoint and source boundary; decompose into bounded lanes; run focused tests/typecheck before the master suite; build only after green source gates; package into a unique candidate directory; explicitly ad-hoc sign and strictly verify; inspect archive readback; and hand off exact commands, hashes, identities, changed files, and unresolved risks. Never copy the Codex tree wholesale.
- The verified Codex commands were `npm run typecheck` plus focused Vitest suites, `npm run typecheck && npm test -- --run`, `npm run build`, and `CSC_IDENTITY_AUTO_DISCOVERY=false npx electron-builder --mac dir --arm64`. The first package attempt failed on `getaddrinfo ENOTFOUND github.com` and was retried only with explicit network approval. This historical evidence does not authorize a new Hermes package.
- Codex and Hermes packages must have distinct bundle identities and user-data profiles before runtime inspection. The Codex artifact used `com.cocombees.prism.codex`/`prism-codex`; Hermes v7 uses `com.cocombees.prismfoundry`. A strict ad-hoc signature and passing archive readback do not establish visual acceptance or approval.
- Merely launching the unsigned/ad-hoc Flight Tester must not decrypt provider credentials, contact provider account/model endpoints, or trigger a macOS Keychain password prompt. Startup may determine connected state only from credential-file presence. Decrypt and refresh provider credentials lazily when the user opens Connections or performs an explicit provider action; never weaken or replace OS-backed secret storage to avoid an internal-build prompt.
- Automatic per-node cost estimates are part of launch rendering, so they must use the audited local, request-shaped pricing catalog and must never decrypt credentials or contact a provider. Only an explicit provider action may access a secret. Keep the local estimator sensitive to model, resolution/quality, duration, quantity, and other billable controls so the estimate is a useful upper-bound preview rather than a generic route-unit guess.
- When reporting a development update, say only that Flight Tester was refreshed/opened. Never include an `.app` link, send or present the `.app` bundle, or describe it as a deliverable unless the user explicitly asks for that internal artifact.
- The user performs the acceptance testing. Until the user has personally tested the complete app and explicitly says the app is finished, never refresh, prepare, label, or present a release build or DMG, and never describe Prism Foundry as finished.
- Existing-candidate inspection stops before candidate approval or promotion. An artifact with incomplete visual/runtime coverage remains unapproved even when its static archive, hash, bundle identity, signature, and automated checks pass.
- A request to fix, test, rebuild, package, preview, or continue development authorizes only a Flight Tester refresh unless the user separately gives the explicit completion approval above.
- Generated single-use Image, Video, and Audio nodes preserve successful result history across reruns. Double-clicking rendered media opens its original full-resolution file in the shared viewer, and the viewer's outer frame follows that image/video's natural aspect ratio while fitting within the viewport. The same viewer opens on double-click anywhere in the non-action bounding box of a Home Assets or Canvas Assets card for materialized single-use Image/Video/Audio, Character, and Location/Background assets; action buttons and rename fields are excluded. All Styles, all Elements, missing files, and non-materialized entries remain selection-only. Node and viewer hover actions are Show in Finder, Rename, Favorite, and Delete; the viewer also exposes Close and, only when multiple generations or eligible views exist, Previous/Next by buttons and arrow keys. A non-maximized node's Previous/Next control is invisible and non-interactive until its media stage is hovered or keyboard-focused. Carousel and viewer direction controls stop pointer/double-click propagation without cancelling their ordinary click events, so they never open preview or drag/focus the node and a double-click advances twice in the selected direction. Media/viewer surfaces disable native selection and image dragging, preventing any browser-selection tint. Ordinary-media Rename moves the physical managed file and rewrites every owning path. Delete moves the guarded physical file to the macOS Trash and removes its registry/history record. Its confirmation layers above the full viewer and darkens the viewer/background beneath it. The footer shows source-input labels, actual resolution or duration, provider model, and local creation date/time. Right-click exposes the type-correct clipboard action. Home Assets and Canvas Assets expose Finder for every user-owned/copyable file or reusable wrapper; built-in Styles expose no file action.
- The full-resolution viewer isolates Close at top-left and keeps file actions top-right. Its metadata strip is an image-bottom overlay rather than a permanent row: hidden at rest, shown only on viewer hover/focus, exactly `70%` opaque, and never reducing the available media height.
- Canvas Assets card actions are hover/focus-only and bottom-right aligned with a consistent inset. They overlay no title or subtitle: both text rows dynamically reserve the action footprint during hover/focus and end in an ellipsis before any icon.
- Every Image Generator, including the defensive legacy Image Editor surface, visibly exposes Format and Image Resolution. Resolution options are selected from an exhaustive capability table for every built-in model/provider route; unknown discovered aliases default to one conservative native tier until verified, never speculative 2K/4K. Provider routes that combine resolution and ratio in one `image_size` field must compile the selected tier and ratio into legal dimensions while respecting maximum edge and total-pixel limits. Every open Image and Video Aspect Ratio menu maps numeric ratios into four text-scale visual archetypes—square, standard, wide, and ultrawide—with portrait rotation inside one balanced `18 × 18px` envelope. Do not draw every ratio literally. The closed selected trigger is text-only and never shows the box. Labeled controls such as Format and Resolution use live parent-row measurement: place labels left only when every label plus selector fits without clipping, otherwise stack above. When stacked, their outer left edge aligns with the quantity capsule below while the right selector edge stays aligned. The parent row owns the responsive query; a control cannot query and restyle itself.
- Resizable generator and node prompt fields retain a visible diagonal resize affordance without a surrounding square, border, or opaque scrollbar corner. Their vertical scrollbar uses a transparent, balanced `10px` outer track with the thumb inset inside that width; the earlier `7px` treatment is too thin.
- Provider-cost display is a traceable estimate, not a quoted maximum. Use live request-specific pricing when available. Variable-token endpoints use an audited size, quality, input-count, and quantity calculation rather than a flat catalog ceiling; store the basis and verification date, refresh stale tables, and prefer authoritative completed-run charge evidence during reconciliation.
- GPT Image 2 Edit uses fal's current high-quality size table with interpolation for custom dimensions and includes the first input image in that baseline. Additional verified input-image allowance may be added, but prompt character count alone is never billed as a deterministic surcharge because fal documents reasoning/prompt complexity as variable.
- Persist complete user-visible wall time and a material-settings timing key for each completed generation. Sequential batches record one full batch observation from the displayed run start through the final result; intermediate provider calls may retain diagnostic duration but never train the visible countdown as fake multiplied batches. Countdown order is provider progress, bounded recent local completions for the exact same model/media/resolution/duration/quantity/reference/audio shape, then a conservative same-model/media/resolution/duration/quantity/audio family fallback when only reference count differs, then a deliberately widened static cold-start range. Exact and family estimates remain above the slowest completion in their bounded recent evidence plus a safety margin, so one fast run cannot erase a known underrun or make weaker family evidence more conservative than exact evidence. A changed reference count must never discard reliable two-minute endpoint evidence and reset the display to a generic one-minute estimate. A remount preserves the original run start time and frozen estimate; an exceeded estimate changes to truthful finishing language rather than counting below zero.
- After explicit completion approval, prepare the intended final user-facing DMG. Signing and notarization still require the user’s Apple Developer credentials and explicit authorization.
