## Visual and interaction QA

- Use flat dark design, original branding, restrained purple accents, and no Magnific trademarks/trade dress.
- Storyboard defines the canonical regional palette for every product node: outer shell and header `#17161b`, body region `#121116`, input/media-well region `#111015`, footer `#17161b`, border `#302d37`, and divider `#2a2730`. Generator, reusable Character/Element/Location/Style, List, Gallery, Router, Storyboard Asset, Prompt, and assistant nodes reuse these values through shared tokens by equivalent region. Semantic accent colors and deliberately black media stages may differ; an entire node family may not drift into a separate darker shell scheme. Equivalent headers use the shared `12px` node-title and `8px` subtitle tokens, while classified compact regional exceptions keep their existing contract sizes.
- Every node header and every terminal painted region owns corner radii matched to its shell, including footerless bodies such as Gallery. Because nodes retain visible overflow for ports and hover toolbars, parent overflow must never be used to conceal a square regional background; no header, footer, or terminal body fill may protrude through the shell's rounded corners at any canvas zoom. Ordinary Image, Video, Upload, and Output media uses a local terminal wrapper for corner clipping only and retains its natural rendered aspect ratio; do not force a 16:9 wrapper, stretch the media to full wrapper height, or remove Output rounding. Fixed ratios remain scoped to intentionally framed or user-selected stages. Inline connected-input tag/rule enclosures have equal top and bottom spacing, visually centering them between the header and the following body region.
- Use the globally enlarged typography scale established in August 2026: outside explicit compact exceptions, every previously fixed UI font size is increased by at least `2px` across menus, metadata, tooltips, headings, and responsive variants. Canvas Assets keeps its accepted header scale, while the category rail, search field, All/Imported/Generated filters, and asset-card title/subtitle receive another `2px` increase plus matching taller controls and cards because the first global increase remained visually imperceptible there. Compact node-control text is deliberately restored to its pre-increase `8px` size for selected model values and their neighboring Quantity/output values, ratio, resolution, Duration, FPS, Sound, Type, and equivalent compact controls; headers remain enlarged. Compact output and node-local empty-state titles use a shared `7px` token: this includes `Output 1–4`, `No Media Yet`, Upload/Choose Media, and equivalent Character, Element, and Location empty titles. Their subordinate `Pending`/Generating/Failed and helper copy use the shared `7px` support token. Outline icons in these compact states use a `1px` stroke—half the normal Lucide stroke—while headers and application-level empty pages remain unaffected. Every node-local `Describe…` prompt and placeholder, connected-input tag, type label such as `Media Collection`, and `HARD RULE` copy retains its classified compact rollback. Automatic Kling routing has no separate visible notice. These exceptions remain regular `400`. Thumbnail view-angle text also retains the original compact `8px` size. Asset names inside reusable Character, Style, Element, and Location selection scrollers use regular `400` weight while retaining their accepted size. Compact text actions such as Storyboard `All` and reusable-asset `Save` use regular `400` weight rather than semibold or bold. In every reusable editor, Search placeholder text and the following `Custom Character`, `Custom Style`, `Custom Location`, or `Custom Element` heading share one exact left edge. Preserve the existing relative hierarchy rather than replacing it with one minimum size. Rebalance shared control heights and allow bounded wrapping or truncation where needed; larger type must never clip, overlap, bleed outside its owner, widen the fixed 315px node standard, or break the 440px application-shell minimum.
- The Magnetic Guides icon visually switches Off immediately on click even while still hovered. Its bright filled treatment belongs only to `.is-active`; the inactive hover state is restrained and neutral, never identical to On. This visual separation must not alter guide enablement, snapping, thresholds, or persistence.
- A locked node never initiates Magnetic Guides and never displays alignment or equal-spacing guides during attempted movement. Reject locked nodes at drag start and clear stale drag/guide state defensively. They remain valid stationary alignment and equal-gap targets for unlocked moving nodes.
- Magnetic Guides uses exactly the concise tooltip `Magnetic Tools` in both states; its visual active treatment communicates On/Off. Recommendation distances, snap thresholds, maximum gaps, Shift-axis details, and state narration remain internal behavior and never appear as debug-like customer tooltip copy.
- Keep Magnetic Guides and manual alignment actions as unwrapped, non-detachable individual tools in the top-right header whenever the window has room. After the separate Magnetic Guides toggle, order the manual tools exactly: Center Y, Center X, Top, Bottom, Left, Right, Equal Horizontal Gaps, Equal Vertical Gaps. Center Y uses the horizontal-centerline icon and gives every selected node the same Y-center while preserving X. Center X uses the vertical-centerline icon and gives every selected node the same X-center while preserving Y. Never swap these icons, axis mutations, labels, tooltips, or order. Match each button to the left tool rail's exact visual language: dimensions, icon scale, radius, neutral surface, light active/hover contrast, and custom tooltip behavior. Disabled alignment commands remain non-interactive but keep the readable `#8e8999` neutral brightness at full opacity so the header never appears substantially darker than the side tools. At the compact header breakpoint only, replace the eight individual alignment commands with a single alignment launcher; clicking it opens a viewport-safe two-row, four-column palette with those same commands and never performs an alignment itself. Dismiss it after a chosen command, outside click, or Escape.
- The packaged macOS app must remain usable at a 440px quarter-screen width. The canvas header is fluid: no 220px brand reservation, no generic `Workflow` word/name field, and no fixed label may force horizontal overflow. At roomy widths show project identity and a Save icon followed only by `Saved`/`Saving…`. At compact widths collapse project identity, Save, Assets, History, and Connections to icon-only controls with custom tooltips; retain Magnetic Guides, compact alignment access, and the current-page deletion action. The brand wordmark may yield before functional controls, but the underlying actions and their state must remain reachable.
- The Canvas top bar leaves an explicit 8px safety gap after the macOS traffic-light clearance before the Prism Foundry brand. At every roomy width, center the project name plus `Saved`/`Saving…` group within the real flexible interval between the brand's right edge and Magnetic Tools' left edge; unequal brand/action widths must never push it away from that interval's midpoint. The project name, `Saved`/`Saving…`, `Assets`, and `History` use one exact label size. The project name alone is semibold; all three status/action labels remain regular `400`. A node-position lock is a persistent current-state toggle: locked shows the closed Lock glyph with the darker pressed surface and highlighted icon, while unlocked shows the open Unlock glyph without that pressed treatment. The tooltip and accessible label still describe the available next action (`Unlock Position` or `Lock Position`).
- Do not expose a freehand Draw tool or `P` shortcut in the Canvas tool rail. Existing persisted Drawing nodes remain readable and renderable so removing the creation tool never destroys prior project content.
- Equal-distribution measurement labels report each segment's actual current edge-to-edge pixel distance while dragging. Do not show the proposed equalized number on every segment before snapping. Automatic equalization ignores a candidate if either its target gap or any currently displayed live gap exceeds 300 canvas pixels; a 301px-or-higher badge must never appear merely because the eventual snap target would equal 300px. The 80 screen-pixel recommendation reach applies only along the equalization axis. A horizontal-gap peer must have genuine vertical bounds overlap with the moving node, and a vertical-gap peer must have genuine horizontal bounds overlap; perpendicular proximity may never pull Video Generator from an upper row into Gallery and Storyboard's row. The 10 screen-pixel snap threshold remains independent. Once the correction enters the snap range, draw and label from the snapped position so all equalized segments end with the same number. Equalization wins an exact zero-correction tie with an ordinary alignment candidate so its dashed meter never disappears at the snap point or flashes between pointer updates. When a vertical gap's centered pixel badge would collide with the selected node toolbar, place the badge immediately beside the toolbar on the side with usable viewport space, then return it to the original centered location as soon as that location is visible.
- Fixed-width product nodes use exactly the Storyboard width of 315px. This includes List, Gallery, Character, Location, Element, Style, Prompt, audio nodes, upscaler, Upload, Output, and other non-adaptive product nodes. Router is the content-fit exception: bound it safely but end its rounded shell immediately after the route text with balanced horizontal padding. Image Generator, Video Generator, and Media may remain wider/adaptive because their stage follows output aspect ratio. Frame, sticky note, comment, sticker, and drawing remain freeform geometry. Normalize legacy persisted fixed-width nodes without moving them or changing their height; remeasure after migration and reflow internal columns and footer controls so no standard causes overflow, clipping, crowding, or loss of function.
- Place the persistent Magnetic Guides toggle immediately left of the top-right manual alignment actions. When enabled, rank eligible targets by visual center-to-center node distance before alignment delta so an oversized Storyboard cannot outrank a genuinely nearer Video Generator merely because its bounding rectangle touches or overlaps the dragged List. Cross-edge alignment remains valid between edges. Center is exclusive to center-to-center alignment: never recommend top, bottom, left, or right to center, nor center to any edge. After choosing the visually nearest eligible node, recommend that node's closest valid horizontal or vertical edge/center relationship. Begin ordinary horizontal/vertical edge or center recommendations within 35 screen pixels, begin equal-distribution recommendations within a separate 80 screen-pixel node-to-node area, and snap either only within 10 screen pixels, with all thresholds normalized against canvas zoom. Equal distribution considers only nodes sharing the dragged node's visual row or column and wins whenever its required correction is smaller than the competing ordinary alignment correction. Draw edge/center guides across the full visible canvas in light cyan at exactly 0.5 screen pixels. Keep measured equal-gap guides locally bounded with a stable zoom-correct 0.5 screen-pixel raster footprint and reduced dash opacity so their perceived weight remains lighter while never falling between device pixels; preserve the explicit 4 screen-pixel cyan dash followed by 6 screen pixels clear. Keep their render identity stable across coordinate updates so dragging updates existing meters instead of remounting them. Add open, outward-facing arrowheads whose tips point against both measured node edges while maintaining a zoom-correct 2 screen-pixel visual gap from each edge, so each gap reads as a distance meter; keep its label equal to the true current edge-to-edge gap until snapping equalizes every segment. This arrow treatment belongs to equalization only and must not alter ordinary alignment guides. Pointer-up, mouse-up, drag-stop, and window blur schedule guide/constraint cleanup for the next animation frame—not the current event stack—so React Flow's final position update commits the snapped coordinates before cleanup; a new drag cancels pending cleanup. Toggle-off may clear guides immediately. Preserve locked nodes as stationary guide targets, and constrain Shift-drag to the dominant horizontal or vertical axis using the current drag event rather than stale modifier state.
- Standardize smallest menu text, selected text, option text, icon size, row height, padding, border radius, and dropdown chevrons globally.
- A `− value +` quantity stepper is not a selector and never receives yellow fill compensation. Size its shell from the currently displayed value only: equal left/right outer padding, equal minus-to-value and value-to-plus visible gaps, symmetric fixed minus/plus tracks, and no longest-option scan. A longer displayed value widens the shell and a shorter value shrinks it. Treat that completed intrinsic width as fixed only while calculating the shared blue gap around other controls in the row.
- Keep the closed selected value on its classified compact scale, but render every shared application-selector option row exactly `2px` larger so browsing remains readable. Explanatory copy aligns to the first visible selected content inside its owning selector—not the outer border—and never floats as an unrelated column label. Content-aware row equalization is global wherever a node region can naturally read as full. Measure every finite selector's longest legal option in painted browser pixels and include every logo/icon, chevron, internal gap, padding, and border. Before adding flexible width, evaluate semantically valid arrangements of peer controls across neighboring lines and select the arrangement that minimizes both total and worst per-control compensation; rearrange controls between lines whenever that reduces empty compensation without changing meaning or priority. After composition is chosen, one fixed blue inter-control gap token applies across every neighboring eligible line, while equal yellow compensation is calculated independently among the flexible selectors inside each individual line. A shorter current selection may visibly leave extra interior blank space because its longest legal option defines the track. Fixed actions may coexist with fillable controls, but Quantity remains intrinsic unless expansion is visually natural, and Settings/Play retain their standardized size and position and never absorb remainder. A fixed child that fills its assigned track caches its intrinsic first-pass width before allocation; later stretched rectangles are never fed back as intrinsic measurements during ResizeObserver updates. Do not align columns across rows. Voiceover retains the approved Model/Voice first line and Language/Output/Speed second line. Because visible labels already explain their selectors, they do not emit detached redundant native-title bubbles.

- Inspector multiline context fields start at no less than three standard control heights, allow vertical resizing only, and clamp both minimum and maximum width to their owning column so pointer resizing cannot create overflow or underflow.
- Prevent borders, bars, buttons, thumbnails, and delete badges from clipping or bleeding past rounded containers.
- Keep controls inside frames at all zoom levels. Dropdowns and popovers are application UI, not canvas content: anchor them to the originating control while making every menu item and purple group heading visibly match that selector's selected-value font size at the current canvas zoom. Derive visible type scale from the React Flow viewport transform, never from element-height ratios. Shared, Storyboard-compact, Prompt Enhance, and autocomplete variants all use one continuous anchoring lifecycle. While open, continuously recompute that anchor, typography, row geometry, and painted-width sizing during canvas pan, zoom, node movement, window resizing, and scrolling; fixed viewport rendering must never leave a menu floating at an obsolete coordinate or using a stale type scale. This is the global picker-sizing rule: derive width from the painted glyph width of the longest visible option or group heading plus its logo/icon, checkmark, and modest padding; allow the portalled menu to exceed its trigger width when necessary while keeping it outside node clipping; clamp that width between the control's practical minimum and the available viewport; cap height to the available space above or below; reposition when needed; and render large sets as one smooth vertical list with a visible scrollbar. Purple group headings use authored Sentence case, never forced uppercase, and compact titles may substitute `&` for `and`. Never inherit a tiny trigger width, split a normal option set into boxed columns, leave menu typography at a stale canvas zoom, or use a fixed oversized panel. Across all visible vertical menu and node scrollbars, reduce both track/thumb thickness and perceived weight to exactly 70% of the previous treatment while retaining clear overflow affordance.
