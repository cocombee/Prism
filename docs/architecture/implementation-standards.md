## Implement as a connected system

- Trace cause and effect from source node through typed edges to the final provider request. Verify hidden prompt/reference assembly in code without spending API credit. Every cross-node resolver change must include a deterministic internal request-audit test with at least fifteen valid linked intermediate nodes, plus a wrong-typed edge hidden at the same depth; prove the source instruction arrives exactly once and the invalid branch fails before provider submission.
- Resolve every authored upstream text source—including a legacy Assistant during migration—exactly once even when Style or another authority reaches the terminal through multiple graph paths. Gallery is a media-only terminal for materialized Image, Video, or Audio; raw Prompt/text and typed text Routers are rejected rather than connected and silently discarded. Legacy generated Output nodes remain source-only materialized results and never gain an inbound socket or appear as new terminal destinations.
- Provider-effective non-Seedance Video prompts use the production shot specification in this fixed order, omitting only sections with no source data: `SCENE CONTEXT`, `ACTIVE REFERENCES`, `REFERENCE MAP`, `LOCATION MAP`, `FIRST FRAME`, `FORMAT MODE`, `CUT 1..N`, `OPTICS`, `CAMERA`, `PHYSICS`, `ACTION`, `PERFORMANCE`, `LIGHTING`, `AUDIO`, `STYLE`, `POSITIVE LOCKS`. Seedance requests instead compile secretly and exactly once into the canonical Seedance order: `ASSISTANT TASK`, `EDIT CONTROL`, `REFERENCE AUTHORITY`, `EDITABLE VARIABLE REGISTRY`, `SUBJECT AND PERFORMANCE`, `CAMERA`, `LENS AND OPTICS`, `LIGHTING`, `LOOK AND CAPTURE CHARACTER`, `TIMELINE AND CONTINUOUS ACTION`, `OPENING-FRAME HARD LOCK`, `IDENTITY AND ANATOMY CONTINUITY`, `WARDROBE, ACCESSORY, AND PROP CONTINUITY`, `SCENE, VEHICLE, AND ENVIRONMENT CONTINUITY`, `CAMERA, FRAMING, AND OPTICAL HARD GATE`, `FINAL-FRAME AND OUTPUT HARD GATE`, `HARD AVOID`. Its `LENS AND OPTICS` motion signature follows the user-selected Motion FPS and defaults to a constant 180° shutter angle so exposure time adapts automatically to that cadence; an explicitly authored shutter angle or shutter speed overrides the 180° default. Emit this cadence/shutter rule exactly once. Coordinated multi-view assets produce one logical reference-authority line per canonical tag. Reference descriptions and identity constants derive only from authored source `prompt`/`stylePrompt`, never Connected Rule prose; remove rule-mode labels and avoid doubled terminal periods. Each fact has one owning section: role identification, description, continuity, camera, style, action and avoidance prose may not be repeated under multiple headings. Quantify every camera choice and omit zero-centimetre shake. For the non-Seedance structure, `REFERENCE MAP` is its own required section immediately after `ACTIVE REFERENCES`; video-only `PHYSICS` follows `CAMERA`; Character-only `PERFORMANCE` is required and untrimmed; `LIGHTING` remains quantified without repeating Style prose while `STYLE` preserves it verbatim. Direction Layer undefined/true remains on. Image prompts retain their still-frame Direction Layer; precise Image Editor requests receive none.
- Keep the complete provider-effective request X-Ray exclusive to developer tests and diagnostics. The production node inspector may expose one collapsed prompt-only preview of the exact composed provider text, including numbered provider-native Kling shot prompts, assembly errors, and a copy action. It must never expose credentials, broker routes, request controls, binary references, or the full request object; internal diagnostics remain sanitized and non-billable.
- The developer-only request X-Ray enumerates every selectable provider-effective control for Image Generator, attribute-only Upscaler, Video Generator, ElevenLabs/Fish voice, and Sound Effects. Model/route choices, model-specific negatives, safety, auto-fix, audio, motion/native FPS, interpolation, generation parameters, and output options must all survive node state → `GenerationRequest` → provider-effective audit; focused tests fail whenever a UI option is omitted. Preserve the fifteen-level valid-chain and hidden wrong-typed-edge audits alongside this complete control matrix. Image Editor is consolidated into Image Generator and legacy projects migrate in place; Music Generator is retired and never appears or runs.
- Maximal non-billable video audits must cover the union of every legal upstream source across separate model-valid topologies: Seedance references (semantic assets, Style, compiled Storyboard sheet, generated/uploaded/upscaled images, generated/uploaded video, Voiceover, Sound Effects, uploaded audio, Lists, Prompt, and fifteen Router levels) plus Kling frame-anchored start/end and video-element paths. A compiled Storyboard connection carries both structured panel semantics and its actual single-image sheet. Every reference declares one domain authority—appearance, storyboard map, motion/camera, or audio/timing—and the final provider prompt preserves authored Magnific-grade camera, lens, light, state-ledger, direction, acceptance, and hard-avoid content exactly once.
- Derive model controls, input limits, duration, ratio, resolution, audio, frame-rate availability, and cost from the selected provider/model capability. Image-reference readiness and Electron-main validation use the same provider-effective endpoint budget; never impose one universal cap across image models or silently truncate submitted references. A reusable multi-view Character remains one logical asset in the UI even though its coordinated views are provider-bound image inputs. Before finalizing a provider control surface, verify every listed model variant against its current official schema; never extrapolate one tier or mode to its siblings. For every finite provider enum or catalog, expose the complete currently supported set for the exact endpoint. Never hand-pick a sample. If the field is open-ended/dynamic and no authoritative complete catalog is available, use a validated free-form field or fetch the full catalog; never disguise a partial list as complete. Unsupported but contextually important controls may remain visible only as clearly disabled, provider-native/fixed values.
- Apply each image endpoint's verified reference budget to the visible Canvas Image Reference port as well as readiness and submission: GPT Image 2 Edit `16`, Seedream 5.0 Pro Edit `10`, Nano Banana Pro Edit `14`, and FLUX Kontext Pro `1`. Ordinary Image/Video media may use generic media/reference inputs only; it can never impersonate Character, Element, Location, or Style on a semantic-role port or connect into those reusable asset nodes.
- A fal.ai Image Generator with any image reference exposes every supported reference-capable image endpoint, currently Nano Banana Pro Edit, Seedream 5.0 Pro Edit, GPT Image 2 Edit, and FLUX Kontext Pro. Preserve the selected endpoint instead of forcing Nano Banana, show the actual model-company logo, and assemble that endpoint's native image field and limits in Electron main. Character completion and ordinary Image Generator reference workflows share this complete catalog; never hide Seedream or GPT Image 2 outside Character creation.
- Native FPS and Motion FPS are separate global video concepts. Native FPS is the real encoded provider frame rate. Motion FPS is visual movement intent and offers exactly `12, 16, 24, 25, 35, 50, 60`; when Native FPS is known, show only Motion FPS values strictly below it, excluding the equal value, while an unknown native rate keeps the full list. In the shared menu, show the purple `Native FPS` group first with the actual lowercase value such as `24 fps`, or the compact value `Native` when undocumented, then the purple `Motion FPS` group with lowercase numeric options. Never use the redundant, truncation-prone text `Provider Native`. Only titles capitalize `FPS`; numeric values always use lowercase `fps`. Compile Motion FPS into the final provider prompt exactly once as held-pose/frame-update intent while explicitly preserving encoded FPS, duration, and playback speed. Never claim that prompting guarantees a different file frame rate.
- Keep credentials and provider calls outside the renderer. Use OS-backed secure storage. Direct OpenAI image edits submit every connected input through the provider-required multipart `image[]` array field, including single-reference edits; never flatten repeated references into a scalar `image` field.
- Treat fal.ai billing visibility and inference permission as separate capabilities. A recommended API-scoped key may receive the exact billing-only `API key is not permitted to perform this action` response while remaining eligible for generation; show credits as unavailable, clear cached failures whenever a credential is replaced or removed, and verify inference only through the real node run without claiming success beforehand.
- Treat an individual fal model route's `Billing hard limit has been reached` response as route-specific until the authenticated account billing endpoint confirms otherwise. Recheck live billing instead of permanently caching a global account block; a positive balance keeps other fal routes usable. Connections shows the authenticated fal account username and live balance so dashboard/account-key mismatches are directly visible without exposing the key.
- Treat provider identity as the exact pair `provider + model` from selection through readiness, encrypted profile resolution, request assembly, progress, errors, history, and output. Never infer the error provider from node kind or default a direct Video route to fal. Use one canonical provider resolver and display-name function at every boundary.
- Separate a provider's static supported catalog from the authenticated account's activated/available catalog. Static models may remain visible for discoverability, but a verified live catalog must never be padded with absent static models. Block an unavailable paid route before IPC, name the exact activation requirement, and allow a successful catalog refresh to clear stale activation failures.
- Direct BytePlus ModelArk uses encrypted multi-account profiles and an async create/poll/download lifecycle. Compile the exact selected model capability, POST once, retain the task ID, poll that task, propagate abort, copy expiring output URLs into managed project storage, and never retry an ambiguous create or fall back to fal automatically. BytePlus resolution authority is tier-specific: direct Seedance 2.5 supports `480p/720p/1080p`; direct Seedance 2.0 Standard supports `480p/720p/1080p/4K`; direct Fast/Mini support `480p/720p`.
- Keep verification bounded and production-real. Use one vertical TDD batch, then focused tests, typecheck, one build/package/open. When the same harness seam fails twice, stop and diagnose or reroute; never loop Electron launches or rewrite expectations repeatedly. Geometry tests use actual production components and production CSS, not replicas. Preserve the next-generation source boundary and never edit legacy renderer files for convenience.
- Treat the project file, canvases, pages, assets, history, node references, and on-disk folders as one persisted project.
- Deleting a Library or Canvas Assets item that is deployed is a project-wide dependency transaction: warn with the affected Canvas-instance count, then remove every matching instance and incident edge from all Canvases and Pages while pruning embedded media references and every active/inactive page snapshot. Never leave a runtime cache that can restore deleted media after navigation.
- Autosave dirty workflow state on a one-minute cadence only. Opening or hydrating a project remains green icon-only `Saved`; React Flow measurement, selection, focus, background normalization, and programmatic viewport restoration are runtime state and never create a false dirty mark. Any real persisted Canvas mutation—including node/edge/content changes, authored text, pointer-driven pan/zoom, and explicit Fit—immediately changes the header control to the earlier subtle-delete red `Unsaved`. The icon-only button remains manually clickable to save now. `Unsaved` appears briefly for two seconds after the first real edit, amber `Saving…` remains only while the write is actually in flight, and the earlier connected-settings green `Saved` stays for two seconds after success; otherwise only the colored save-icon button remains. Every transient label is a separate sibling outside the bordered icon button, immediately to its right in one horizontal row, using the project-name topbar size with regular `400` weight. Use a user-action gate, identical bordered icon geometry, and a mutation version so background hydration never dirties the project and edits made during an in-flight save return to `Unsaved` instead of being falsely marked saved. Measure the next automatic checkpoint from the last actual save so repeated edits cannot postpone persistence indefinitely, and never perform sub-minute workflow writes automatically. Keep the top-right Delete and Settings controls neutral like History; connection state never recolors Settings green, and Delete becomes red only inside destructive confirmation/context surfaces.
- Keep logical asset identity separate from media filenames. Every categorized reusable asset name uses the same canonical format as a node tag: Unicode-aware lowercase words joined by single dashes, such as `yusuf-anaqi`; the node tag adds only the leading `@`. Cards, libraries, metadata, rename fields, and export names show the canonical name without `@`. Normalize every reusable save, rename, and legacy load migration through that one rule. Reusable multi-view Character and Element assets are named and exported as one `.prismasset` package; never present each internal rendered view as though it were the asset itself or invent a `.jpg` suffix for the package. Saving a Character preserves its editable managed views and privately rebuilds one high-resolution compiled reference sheet; that derivative is excluded from every Character editor, rail, card, expanded preview, Assets list, and ordinary export, replaces the prior derivative on update, and is the sole downstream provider image for that Character. Every categorized reusable asset displays only its logical asset name across nodes and Assets surfaces, never an internal `.jpg`, `.png`, `.webp`, or other member extension. Ordinary Image, Video, and Audio files retain their real filenames and extensions, but every Rename field edits the basename only and never displays a recognized media suffix. Committing Rename preserves the existing on-disk extension byte-for-byte even when the user types another extension; changing format requires a dedicated conversion/export workflow that actually transcodes the media. A Rename action must update the canonical logical asset, every referencing node, library/card, and export name together—never only its visible `@tag`. On project load, migrate a legacy edited semantic `@tag` into the canonical logical asset name when it differs from the persisted node title, without overwriting an unchanged/default tag. Single-image results such as generated backgrounds and individual Storyboard panels may use `.jpg` only when JPEG is their real output format.
- Canvas paste accepts both macOS `⌘V` and `Ctrl+V` when no editable field owns focus. A copied supported image file or OS clipboard bitmap becomes a managed imported Image asset at the last Canvas pointer position, falling back to the visible viewport center. Preserve original PNG/JPEG/WebP/GIF files when the clipboard exposes file URLs; encode only a raw clipboard bitmap as PNG with its alpha channel intact, never through a canvas, JPEG conversion, or white/black matte. Prism's private copied-node marker must distinguish node paste from external image paste, while unrelated clipboard text produces no Canvas asset.
- Every prompt surface that can receive connected inputs uses the same `@asset-name` editor. Typing `@` searches the canonical tags of compatible real Canvas sources; pointer selection, Enter, Tab, or finishing an exact available tag creates the typed edge exactly once through the shared connection-compatibility and input-cardinality validator, including any established provider-model adoption needed to expose that real port. An already incoming image or other source activates its exact visible canonical tag immediately. Exact connected tokens render purple, while disconnected or prewritten unmatched tokens remain ordinary text without deletion; adding or restoring the matching edge activates them immediately and removing the edge deactivates them immediately. Duplicate Canvas tags never guess a source. Removing prompt text never silently disconnects a graph edge. The graph remains the sole activation truth.
- Renaming from a Canvas node, Home Library, Canvas Assets, or the eligible full-resolution viewer is one asset-level transaction. Ordinary media renames its managed file and every owning node title/tag/path; reusable collections rename every member metadata record, every linked Canvas node/reference, every Library/Assets card, and future export identity together. Protected non-renamable surfaces—including built-in/application Styles—expose no rename action or editable tag. Every live connected-input row, prompt token, selector, and Canvas label immediately shows the new name. Legacy persisted sources whose canonical `referenceTag`, title slug, or reusable metadata name differ expose those identities as graph-backed prompt aliases so an exact authored legacy tag becomes active globally while the asset is connected; autocomplete continues to prefer the current canonical visible tag. In every actionable connected-input row, the `Guide | Auto | Lock` pill is right-fixed and can never be pushed or clipped outside the row; tag and role text own only the remaining left space and ellipsize independently when they do not fit. Do not spend the row on duplicated rule prose; its tooltip may retain the explanation.
- The shared `@asset-name` editor's transparent native textarea and visible highlighted paint layer must wrap against the exact same live text-content width. Derive it from textarea `clientWidth` minus horizontal padding after value changes, resizing, and scrollbar appearance; add only the paint layer's own padding/borders, keep its minimum width at zero, and use identical wrapping rules. Never size it from the outer shell or `offsetWidth`. A long paste must keep the visible caret, selection, Backspace, and Delete position on the same rendered line.
- Treat every `− value +` quantity stepper as a content-intrinsic exception to selector equalization. Its shell follows only the currently displayed value, uses equal left/right outer padding and equal minus-to-value/value-to-plus gaps, never scans the longest legal quantity, and never absorbs yellow row compensation. Include its resulting fixed width only when calculating the shared blue gap around neighboring controls.
- Keep self-contained generators self-contained. Voiceover, Sound Effects, and any retained legacy Music node own their complete prompt/script fields and expose no upstream input socket or Prompt/Router destination; Image and Video remain the broad multi-upstream generator exceptions. Every broad multi-upstream generator uses the same exact-port-derived, role-specific input-tile system, so Image may never regress to one generic Add Reference control while Video exposes its full typed grid.
- Every Video Generator model exposes separate Prompt, Storyboard, Character, Element, Location, and Style typed inputs. Capability-specific Start Frame, End Frame, Image Reference, Source/Reference Video, and Audio Reference ports extend that common semantic set without collapsing Character/Element/Location into one ambiguous socket. Storyboard panel controls remain user-facing shot/camera choices; provider-family recipe labels such as `WAN RECIPE` are forbidden in the UI because family translation belongs only to hidden request assembly.
- Model labels are display-only Title Case across every selector and menu, preserving established acronyms such as `GPT`, `FPS`, `AI`, `O3`, and `4K`; provider IDs remain byte-for-byte unchanged for requests.
- Treat each node's declared typed input ports as the single connection contract, including `maxConnections`. Derive forward/backward quick-connect choices, destination handles, and input cardinality from those declarations through the same central commit validator; never maintain parallel per-signal target lists or handle-name exceptions. Single-value Start/End/Video/Storyboard/Style/Router inputs accept one, Seedance video/audio reference inputs accept three, and collection/reference/text ports remain intentionally unbounded. A property regression must prove that every advertised or validator-accepted route lands on a socket the exact target model declares and cannot exceed its limit.
- Keep Upscaler provider-truthful and typed. `Clarity Image Upscaler` uses `fal-ai/clarity-upscaler` with one Image input; `RealESRGAN Video Upscaler` uses `fal-ai/video-upscaler` with one Video input. The model switch changes the typed socket/output atomically and clears incompatible stale output. Neither mode accepts or submits a prompt. Image preview inherits the real source aspect ratio and becomes one clipped-label draggable Before/After wipe after output; Video uses an aspect-preserving playable preview. Size `2×/3×/4×` only to its longest legal item, keep quantity intrinsically symmetric, right-align fixed-size Options/Run, and leave no unexplained footer strip.
- Reusable-asset save and rename fields never force or seed title-case capitalization. Seed them from the canonical lowercase logical name, permit natural raw typing, disable automatic capitalization/correction, and normalize only when the user commits.
- Make hover, click, drag, scroll, zoom, keyboard, context-menu, empty, loading, running, stopped, error, and completed states explicit and testable.
- Reserve the visible grab hand and primary-button canvas grab mode exclusively for holding Space before text editing begins. The Select tool temporarily swaps its arrow glyph to Hand while Space is held; there is no persistent Pan tool or `H` shortcut. Ordinary node hover and movement keep the normal pointer, explicitly overriding React Flow's built-in selectable, draggable, and dragging grab cursors. While an input, textarea, select, or content-editable field owns typing focus, Space inserts a normal character and never pans; Escape/blur ends that text-editing focus before Space-pan can activate again.
- Use one hover-first socket lifecycle globally. Every real React Flow handle is permanently measured at the outward deployed-icon centre before hover or pointer-down; only its painted child slides inward to stow and outward to reveal. This prevents a new temporary wire from caching the node-body coordinate and guarantees every new or existing wire begins behind its output icon. Preserve a continuous pointer corridor from node body to icon with an overlapping transparent pseudo-element extending toward the node; both the measured handle and painted icon remain exactly 32px and coincident, so enlarging hit-testing can never shift the wire endpoint or leave a floating gap at any zoom. Hovering anywhere on a node reveals only currently stowed input/output icons with one smooth eased transition; a painted icon already deployed because it is occupied, an origin, compatible, or accepting must never receive a second hover translation. After clicking a port, keep that exact origin/destination icon deployed for the full quick-connect picker lifetime and retract it only after selection or cancellation; the user must never lose the initiating socket before choosing the new node. Leaving smoothly retracts every other unoccupied painted icon while its invisible real handle remains outward, so only occupied inputs/outputs remain visible. Disable pointer hit-testing on an unoccupied stowed handle until node hover reveals it. During a live drag, apply incompatibility hiding only to opposite-direction candidate ports; same-direction ports remain in their ordinary idle lifecycle because output-to-output and input-to-input are not candidate connections. A node may never connect any output back into any input on itself: central validation rejects the edge before type compatibility, and all opposite-direction ports on the origin node hide as invalid candidates even when their signal types match. Central typed validation still retracts and hides an occupied incompatible candidate's painted icon, but its existing measured edge anchor and wire stay fixed at the deployed icon centre with no inward wire animation. Icon visibility guidance and existing-wire geometry are independent; cancelling the drag or completing any valid connection smoothly restores the occupied icon over its unchanged anchor.
- Migrate older saved graphs that exceed any declared port cardinality by retaining the first edge in stable array order, disconnecting only the surplus, and showing one explicit notice naming the affected sources and reason. New drags and quick-connects reject the surplus before creating an edge, while provider assembly independently rejects any invalid persisted graph; never silently overwrite or partially combine competing single-value authorities.
- A stale compiled Storyboard remains a valid text-only shot plan but visibly warns that its saved sheet has unsaved panel edits and must be recompiled to include the current visual map. The warning must not block generation. Library selection preserves `storyboardNeedsCompile` exactly and may never launder a stale sheet clean.
